### 实现要点（8 处改动）
1. **i18n**：加 `smart.3dFov = {zh: "焦距", en: "Focal length"}`，i18n 校验通过。
2. **辅助函数**（`smart-canvas.js:9015`）：
   - `smart3DCurrentFov(node)`：优先 `node.camera.fov` → 场景 `camera.fov` → 45，并做 20–90 范围合法。
   - `smart3DFocalMm(fov)`：35mm 全画幅等效 `f = 12 / tan(fov/2)`（传感器高 24mm → half=12mm），边界保护 tan<=0 时回退 50。
3. **`smart3DBodyHtml` 加 fov 行**：在 `.smart3d-bar`（运行按钮之前）插入 `<div class="smart3d-fovrow">` 含滑块 + 读数 `<span data-3d-fovval>`。

   - `change`（松手）：写 `node.camera.fov` + `scheduleSave()`。
   - 必须 `e.stopPropagation()`，否则节点拖拽抢走鼠标事件（`beginNodeDrag` 的 `el.onmousedown` 排除链要相应放过 `[data-3d-fov]`）。

1. **删除按钮悬空灰晕**（最明显）。`getComputedStyle` 显示按钮 `box-shadow: rgba(15,23,42,.12) 0 8px 18px` + `backdrop-filter: blur(10px)`，而背景被全局 `.image-node:not(.empty-node) .node-delete` 置为 `transparent`。像素扫描（2x 图，行 y=200）实测按钮左右各一条 (245~249) 灰带、下方 y=226~234 为 (235~239) —— 一个透明按钮拖着阴影，就是一块悬空灰晕。其他节点看不到是因为 `.node-head` 被全局 `display:none`，只有 3D 节点会显示标题栏。
2. **删除按钮没有 hover 反馈**。全局 `.image-node:not(.empty-node) .node-delete`（3 个类）优先级高于 `.mini-x:hover`（2 个类），所以 hover 时既不变红也不加底色，只剩 `.mini-x:hover` 的 1px 位移。CSSOM 核对确认：静态设色规则最高优先级 4（`.theme-dark .image-node:not(.empty-node) .node-delete`），而 `.mini-x:hover` 只有 3。
3. **标题栏与舞台双线**。标题栏 `border-bottom:1px solid #e8edf3` 与舞台 `border-top:1px solid rgba(148,163,184,.32)` 相邻（间距 0），叠成 2px 双线。像素实测 CSS 118.0→(232,237,243)、119.0→(221,225,232)，两条各 1px。
4. **标题栏左缩进比舞台多 12px**。`.node-head{padding:0 10px 0 12px}` + 节点 `padding:12px` → 标题 x=145，而舞台 x=133。焦距行 `.smart3d-fovrow{padding:0 2px}` 也让左侧图标与「45°·29mm」比上方控件行各错开 2px。

### ⚠️ 关键坑：`<select>` 的截断无法用 DOM 检测

`sel.scrollWidth === sel.clientWidth` **恒成立**（92~130px 全扫过），所以第一版探针用
`need > clientWidth - padding - border` 判定截断，得出「英文 480px 未截断」的**错误结论**，
与截图矛盾。真因是**原生下拉箭头独占约 19px**，不出现在 padding / border 里。

**定标方法**（可复用）：单独造一页，同规格 `<select>` 宽度 96~120px 步进 2，`--force-device-scale-factor=3`
截图，然后按「**墨迹右边缘是否随宽度增长**」判定：
- 未截断时墨迹右边缘恒定（= 左内边距 + 文本宽）；
- 截断时省略号贴住文本区右缘，墨迹右边缘**随宽度线性增长**。

定标结果：文本 71.1px 时，**104px 起完整显示**（104 - 2 边框 - 12 内边距 - 71.1 = 18.9 ≈ 箭头宽度）。
代码里取 110 留 6px 余量。

### 改法：阈值按实测文案宽度算，不再写死像素

```js
const SMART3D_SELECT_MIN_W = 110;
function smart3DTextWidth(text, weight){ /* canvas 2D + body 实际字体栈 */ }
function smart3DBarNeedWidth(metaText, runText){
    const metaW = 12 + 5 + smart3DTextWidth(metaText, '800') + 16 + 2;
    const runW  = 12 + 5 + smart3DTextWidth(runText, '850') + 22;
    return metaW + runW + 18 + SMART3D_SELECT_MIN_W * 2;
}
// narrow = smart3DLayoutSize(node).width - 24 < smart3DBarNeedWidth(objectsText, runWidest)
```

要点：
- **字体必须取 `getComputedStyle(document.body).fontFamily`**（`'Inter',-apple-system,BlinkMacSystemFont,"Segoe UI",sans-serif`）。
  第一版隔离探针里写了「Microsoft YaHei」，量出 76px，与应用的 71.1px 差 5px，定标会偏大。
- **run 的三种文案宽度不同**（生成 3D / 重新生成 / 识别中…），取最宽的算阈值，否则点「生成」的瞬间
  阈值变化会让节点闪一下布局。
- 窄态下 `.smart3d-run` 也收成纯图标（CSS 隐藏其 `span`），文案保留在 `title`。
