```

  ├─ 派生该副本：--apply-update <zip> <dest> <waitPids> <launchExe>
  └─ 自己退出（释放文件占用）

  ├─ 等 PID 退出 → 备份 → 解压 → 剪枝 → 删包

```

- 副本用完**无法自删**（它就是正在运行的映像）→ 由**下次启动的启动器**清理
  `data/_apply_update_*.exe`。
- ⚠️ `Main(string[] args)` 里 `--apply-update` 分支**必须排在单实例互斥量之前** ——
  此时旧启动器可能还没退干净，走正常分支会被互斥量挡下并弹「已在运行中」。

### 包内新增 `release-manifest.json`（`tools/release.py`）

`{format, version, kind, prune_roots, files:{relpath: sha256}}`，作为**虚拟 zip 条目**
塞进包内（`write_zip(..., extra=...)`）。

**为什么放包内**：避免让 C# 再维护一份目录清单（本项目已踩过「两处清单不一致」的坑）。
`prune_roots` 由 `PROGRAM_DIRS` 派生，是执行器剪枝的**唯一权威来源**。

### 执行器步骤（`launcher/UpdateApplier.cs`，374 行）

| 步骤 | 要点 |
|---|---|
| ① 等 PID | 启动器 + 服务，120s 超时；**超时即中止、不改盘** |
| ② 读清单 | 缺清单或 `kind != full` 直接中止 |
| ③ 备份 | 只备份「sha256 会变」的旧文件 → `data/update_backups/<时间戳>/`（日常几 MB，而非整目录 156 MB） |
| ④ 解压 | 剥掉包内顶层目录；**每条做路径越界校验**（防 `../` 穿越） |
| ⑤ 剪枝 | 只删 `prune_roots` 内且不在新清单里的文件；另有禁用名单（`data/assets/output/API/.git/.workbuddy-ai`）作二次防线 |
| ⑥ 收尾 | 删包 → 备份保留 10 个 → 拉起启动器 → 日志写 `%LOCALAPPDATA%\InfiniteCanvasLauncher\update.log` |

## 真实发布包端到端验证 + 两处加固（提交 `d470724`）

之前只用手工造的测试包验过执行器。这次用**真实 111 MB 发布包**跑了一遍，并复现生产路径。

### 🔑 复现生产路径（这是关键，之前没做）

之前是拿仓库根的 exe 直接跑 `--apply-update`，**正本 exe 根本没被占用**，等于没测到
「副本放 `data/` 才能覆盖安装目录里的正本 exe」这条设计。正确做法：

1. `shutil.copy2(真实exe, <install>/data/_apply_update_999999.exe)`
2. 用**那个副本**去跑 `--apply-update <pkg> <install> "" ""`
3. 断言 `<install>/Lochou启动器.exe` 的 sha256 == 包内 exe 的 sha256

实测通过 → 设计成立。

### 结果 15/15

退出码 0 / 46.9s 解出 2012 文件 / 用户数据 10 项 md5 未变 / 2012 文件 sha256 全对 /
5 个旧残留被剪 / `prune_roots` 外文件与 `data/` 用户文件都在 / 随包资源
`inspire_prompt_zh.json` 已更新 / 备份 6 个文件且内容 == 旧版 / 包已删 / 正本 exe 已替换。

### 暴露的两个缺口（已修）

1. **残留下载包没人清**：`TryDelete` 是**静默**的，被占用或中途崩溃就残留 111 MB；
   下次更新到新版本用新文件名 → 旧包永远留着。→ 新增 `CleanupStaleDownloads(root)`：
   `*.part` 无条件删（单实例互斥量保证没有并发的下载），`*.zip` 只清 **2 天前**的
   （⚠️ 用户点完更新又立刻重开启动器时，执行器正在读那个包，无条件删会中断更新）。
2. **可能起两个执行器**：点完「立即更新」启动器 1.5s 内退出，用户马上重开再点一次 →
   两个执行器同时往同一个安装目录解包 → **目录会被写坏**。→ `HandleStartUpdateAsync`
   开头加 `Program.IsUpdateInProgress(root)`（判据：正在运行的映像文件删不掉），
   拦下并提示「已有一个更新正在进行中」。UI 上按钮在下载期间本就禁用，这是第二道保险。

### 踩坑

1. 🚨 **测试脚本自己开着 `ZipFile` 句柄会让执行器的删包静默失败**，误报成「执行器没删包」。
   → 读清单用 `with zipfile.ZipFile(...) as z:`，**跑执行器之前必须关掉**。
2. ⚠️ **验证「字符串是否进了 DLL」要分两个堆**：字符串**字面量**在 `#US`（UTF-16LE），
   **方法名**在 `#Strings`（UTF-8）。搜 `IsUpdateInProgress` 用 UTF-16 会 MISS，
   别据此判定「没编进去」。
3. **跨类调用**：`LauncherHost` 调 `Program` 的静态方法，方法必须是 `internal`
   （`private static` 报 CS0122）。
4. `shutil.rmtree` 删 2012 文件 + WebView2 目录（191 文件）时**会被 SIGTERM 打断** →
   放后台任务跑，别放前台。
5. 顺带确认 exe 能正常起 WebView2（用户数据目录生成了 191 个文件），不是启动即崩。
