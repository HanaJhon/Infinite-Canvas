## 11. 附件节点 + 内置办公 skills（画布 ↔ 画布 Agent 打通）

**需求原话要点**：画布支持上传任意附件、LLM/Agent 生成任意格式附件节点、可下载/点开浏览、Agent 能上传非图片附件、用户能把画布附件发给 Agent、所有 Agent 装基础办公 skills、产物不限一张图、Agent 产物一律落成画布节点。

**三个已拍板决策**：复用现有 `smart-image` 节点承载附件（不新增节点类型）／办公库**离线内置**（whl 进 `packages/` 并预装便携 Python）／预览程度 = **原生预览 + Office 下载**。

### 11.1 关键实现落点
- 附件 = `images[]` 里 `kind ∈ 'file'|'text'`（pdf/docx/xlsx/pptx/zip/txt/md/csv…）。**不存在独立文件节点类型**。
- 前端：`isSupportedUploadFile` 改「除本机可执行/脚本外全放行」；`mediaKindForFile` / `isTextMediaItem` / `isFileMediaItem` 修掉 .docx/.xlsx/.pdf 被误判成 image 的老 bug；新增 `isAttachmentMediaItem`（= 非图片/视频/音频）+ 预览路由 `attachmentPreviewKind`（pdf→新标签内联、text→画布内弹窗、其它→下载）。
- 后端：`content_type_for_path` 补全 OOXML/pdf/zip/文本 MIME；`CanvasLLMRequest.files`；`agent_files_context_block()` 把附件正文（docx/xlsx/pptx/pdf 抽文本，抽不出降级给本机绝对路径让 Agent 自己 `read_file`）注入 message。
- canvas_ops 新协议：`create_file_node` / `attach_file` / `create_attachment_node` / `create_document_node`，**可一次多条、可与 `create_node` 混用**；这类 op **不受「画布控制」开关限制**（是产出通道）。

## 13. 本轮（老板截图反馈）：附件「裂图标」→ 文件名芯片 + 文本类正文进「上游输入」

老板原话：「**xlsx这类无法直接预览的文件直接以文件名的形式呈现，不要用裂图标，txt等文本类文件，以上游输入的形式呈现文本内容**」

### 13.1 根因：4 处渲染点都把 file/text 当图片渲染
`<img src="....xlsx">` 只会得到浏览器默认的**裂图标**。4 处全中：
`renderInputThumbsRow()`（输入框上方缩略图）、`smartNodeInputThumbsHtml()`（节点输入缩略图）、`mentionTokenMediaHtml()`（`@` 令牌）、`mentionOptionMediaHtml()`（`@` 素材面板）。
→ 新增 `mediaFileChipHtml(img, extraClass)`（「格式标签 + 文件名」芯片，`attachmentExtLabel` + `img.name`），4 处对 `kind ∈ file|text` 全部改走芯片；**芯片不挂「图N」角标**（语义不对），节点输入区加 `.is-fileish{grid-column:span 3}` 让文件名放得下。
→ 顺手把 `mentionTokenMediaHtml` / `mentionOptionMediaHtml` 也补了 `file|text` 分支（此前落进 `smartPreviewImgHtml`）。

### 13.2 文本类正文进「上游输入」（懒加载 + 落盘缓存）
- `upstreamTextFileItems(node)`：**必须返回节点里的真实 item 引用** —— `imagesForNode()` 返回的是带 `nodeId` 的**副本**，往副本写 `textContent` 不落盘（这是本轮最容易踩的坑）。
- `ensureUpstreamTextContents(node)`：`fetch(attachmentInlineUrl(url))` 抓正文 → 写 `img.textContent`（上限 20000 字）→ `scheduleSave()`；**失败也写空串**，否则每次渲染都会重试同一个坏文件。
- `inputAttachmentTextFor(node)` → 并入 `inputPromptTextFor()` 的返回值 → 出现在 `renderInputPromptPreview()` 的「上游输入」区。
- `renderInputPromptPreview()` 首行 `ensureUpstreamTextContents(node).then(changed => { if(changed) renderInputPromptPreview(node); })` —— 异步，天然终止（抓完 `textContent` 变字符串，下次没有 target）。

## 14. 移除「附件」创建卡片（老板：附件模块就是快速生图模块）

老板原话：「**附件模块好像就是快速生图模块，所以帮我移除或隐藏附件模块，用户用快速生图即可**」

### 19.3 顺手发现的两个「遮罩其实没生效」的真 bug（后端）
1. **遮罩尺寸不匹配**：`prepare_reference_for_multipart()` 会把基准图缩到 1536，而遮罩以前是 `output_file_from_url()` **原样上传** → 大图裁切时「基准图 1536 / 遮罩 4096」，上游要么报错要么错位贴。
