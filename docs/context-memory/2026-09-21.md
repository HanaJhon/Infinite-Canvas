### 第 1 件：圆角根因与修复
- **本机是 Windows 10 build 19045**（不是 Win11）→ `DwmSetWindowAttribute(Handle, 33, DWMWA_WINDOW_CORNER_PREFERENCE)` 在 Win10 上是**空操作**，所以圆角**完全**靠 `SetWindowRgn(CreateRoundRectRgn(...))`。而 Region 是 **1 位掩码、没有任何抗锯齿** → 天生台阶状。
- 第二个（更关键的）问题：`CornerRadius = 24` 是**写死的设备像素**（且被当**直径**用 → 实际半径 12 设备像素）。**实测本机缩放 175%**（`GetDpiForWindow = 168`）→ 12 设备像素 = 6.9 逻辑像素，圆角又小又毛糙。
- 第三个问题：csproj **没有** `ApplicationHighDpiMode` → .NET 默认 `SystemAware`，在非系统 DPI 的显示器上会被 Windows 整体位图拉伸（文字发虚、圆角被放大成块状锯齿）。
- 修复（3 处）：
  1. `launcher/InfiniteCanvasLauncher.csproj` 加 `<ApplicationHighDpiMode>PerMonitorV2</ApplicationHighDpiMode>`。
  2. `launcher/Program.cs`：常量改 `CornerRadiusDip = 12`（逻辑像素），`UpdateFormRegion()` 里 `diameter = round(CornerRadiusDip * DeviceDpi / 96) * 2`。
  3. 构造函数订阅 `DpiChanged` → 跨显示器时重算区域。
- 实测取证：启动启动器 → `GetProcessDpiAwareness` = **2 (PER_MONITOR_DPI_AWARE)**（修复前是 SystemAware=1）；`GetDpiForWindow` = **168（175%）**；窗口 1100×620。圆角圆弧由 12 设备像素 → 21 设备像素。
- ⚠️ **没能在无头/后台环境里截到启动器窗口**：`PrintWindow` 对 WebView2（DirectComposition）返回全黑；`SetWindowPos(HWND_TOPMOST)` + 屏幕抓取仍抓到的是前景的 Photoshop（z 序抢不到）。**结论：启动器的视觉验证只能由老板本人看**，别在这上面耗时间。
- ⚠️ **`ApplicationHighDpiMode` 不进 exe 内嵌清单**（它是喂给 WinForms 源生成器的「编译器可见属性」，生成的是 `ApplicationConfiguration.Initialize()` 里的**运行时调用**）→ 「grep 清单没有 dpiAwareness」**不能**作为「没生效」的证据，必须实跑 `GetProcessDpiAwareness`。

## 【21:20 之后】修掉老板提的两个启动器 bug（进度条恒 0% + 3000 读不到启动器保存的 API 配置）

老板原话：
> 「更新进度仍然没有实时显示而是始终显示0%，另外启动器中保存的api服务在启动项目（127.0.0.1:3000）中没有被读取到」

### Bug 1 —— 更新进度条恒 0%（实为「宿主没把消息推上来」，不是前端问题）

**根因（已钉死）**：`SendToWebView` / `SendLog` 以前走 `webView.BeginInvoke(...)`。
WebView2 的 **HWND 是异步创建的**，句柄未就绪时 `BeginInvoke` 抛
`InvalidOperationException`，而外层 `catch {}` **静默吞掉** →
**所有** `UPDATE_PROGRESS` / `LOG` 推送全部丢失 →
前端进度条全程停在 0%（但下载本身成功、备份也写了，所以表现为「更新成功但进度不动」）。

**排除项（都验过）**：前端监听器字段名正确（`percent`/`received`/`total`）；C# 下载循环
算出的 `total` 非 0（GitHub 实测带 `Content-Length = 67029263`）；1.1.3 与 1.1.4 的
C# 更新代码逐字相同；`SendToWebView` 的 JSON 封装正确。

**修法（已落地 `launcher/Program.cs`）**：
1. 新增字段 `private readonly SynchronizationContext? uiContext;`，在构造函数
   （由 `Application.Run` 的线程调用）里 `uiContext = SynchronizationContext.Current;` 捕获。
2. 新增 `PostJsonToWebView(string json)`：
   - `form.InvokeRequired` 时优先 `form.BeginInvoke((Action)Deliver)`（**窗体句柄在
     `Application.Run` 之前就已创建，最稳定**）；
   - 窗体句柄未建好则降级 `uiContext.Post(_ => Deliver(), null)`；
   - 不在后台线程时直接 `Deliver()`；
   - 最外层 `catch` 里再兜一次 `uiContext.Post` —— **宁可偶尔在非 UI 线程投递，也不静默丢消息**。
   - `Deliver()` 内部 `webView?.CoreWebView2` 判空后再 `PostWebMessageAsJson`。
3. `SendToWebView` 与 `SendLog` 都改走 `PostJsonToWebView`。

**验证方式 + 结果（模拟测试，脚本已跑完并清理）**：打桩 `window.chrome.webview`
（实现 `postMessage` + `addEventListener`），按 C# 真实格式回放 `UPDATE_PROGRESS`，
再用 headless Edge `--dump-dom` 读 DOM 文案。结果：

```
sent=0    → 正在下载更新包 / 63.9 MB（0.0%）
sent=1    → 正在下载更新包 524 KB / 63.9 MB（0.8%）
sent=12   → 正在下载更新包 7.7 MB / 63.9 MB（12.1%）
sent=34   → 正在下载更新包 21.6 MB / 63.9 MB（33.8%）
sent=58   → 正在下载更新包 37.1 MB / 63.9 MB（58.1%）
sent=79   → 正在下载更新包 50.6 MB / 63.9 MB（79.2%）
sent=97   → 正在下载更新包 61.9 MB / 63.9 MB（96.8%）
```

⇒ **前端渲染完全正确**，与「宿主没推上来」的结论互相印证。

### Bug 2 —— 启动器保存的 API 服务在 127.0.0.1:3000 读不到（端口复用不校验 root）

**根因（已钉死）**：`HandleStartServerAsync` 过去只要 `ProbeAsync(appUrl)` 为真
（3000 上有**任何** HTTP 服务）就**无条件复用**并 `OpenInDefaultBrowser`，
**完全不校验那个服务是不是从同一个 `root` 起的**。老板真实处境：

| | 路径 | `data/api_providers.json` |
|---|---|---|
| A 安装目录 | `…\Infinite-Canvas-Full-1.1.1\Infinite-Canvas` | **2 条**（Coder + Grsai） |
| B 开发仓库 | `…\Infinite-Canvas` | **`[]`（空，今天 10:27 被写空）** |

老板装的是 A 的启动器（写配置写进 A），但 3000 上跑的是 B 的 `main.py`
→ 被复用的服务读的是 **B 的空配置** → `/api/providers` 只返回
`default_api_providers()`（runninghub + volcengine）→ 老板保存的服务「消失」。

**修法（已落地，两侧都改）**：

`main.py`：
- 新增 `_root_fingerprint()`：`sha1(normcase(realpath(BASE_DIR)).encode("utf-8","surrogatepass"))[:16]`，
  同一物理目录的多种写法（大小写 / `..` / 末尾分隔符 / 软链接）得到同一指纹。
- `/api/app-info` 新增三字段：`app_root`(= `BASE_DIR`)、`root_fingerprint`、`pid`
  （**原有字段一个没动，向后兼容**）。
- `__main__` 改为 `argparse` 解析 `--port`（默认仍 **3000**，`parse_known_args` 容忍未知参数），
  启动器在 3000 被占时可把服务拉到空闲端口。

`launcher/Program.cs`：
- 新增 `RemoteIdentity` 结构体 + `FetchRemoteIdentityAsync()`（GET `/api/app-info`，
  拿不到 / 非 JSON / 无 `root_fingerprint` 与 `app_root` → 返回 **null**）。
- 新增 `ComputeRootFingerprint()`（**与 Python 侧同算法**：`Path.GetFullPath` →
  `/`→`\` → `TrimEnd('\')` → `ToLowerInvariant()` → UTF-8 → SHA1 → 前 8 字节 hex）。
- 新增 `PickFreePort()`（`TcpListener(IPAddress.Loopback, 0)` 让 OS 分配后立刻释放）。
- 新增 `ParsePortFromUrl()`；`appUrl` 从 `readonly` 改为**可变**并新增 `int port` 字段。
- `StartServer` 改为 `StartProcess(python, $"main.py --port {port}", root, true)`。
- `HandleStartServerAsync` 判分三支：
  1. **同源** → 复用（日志：「检测到同源后端服务已在运行…」）；
  2. **不同源** → **不复用**，`PickFreePort()` 换端口 + 打印占用者 root 与自己 root 的对比；
  3. **无身份信息**（旧版 / 其它程序）→ **不复用**，同样换端口。

**验证结果（两轮，脚本已清理）**：

① 跨语言指纹一致性（C# 独立小程序 vs Python）——同一目录的 5 种写法**全部**得到
`43c5720d9219b130`（开发仓库）/ `da81e9509deefe41`（安装目录）。

② 判定逻辑三场景（两个真实 HTTP 服务扮演 A/B）：

| 场景 | 新逻辑 | 老逻辑 |
|---|---|---|
| 启动器=A，3000 上=**B** | `start-new`（不同源，不复用） | `reuse` ← **bug 来源** |
| 启动器=A，3000 上=**A** | `reuse`（同源，正常复用） | `reuse` |
| 3000 被无关程序占 | `start-new`（无身份，不复用） | `reuse` |

③ 端到端：真跑 `main.py --port 4094` → `/api/app-info` 返回
`app_root=D:\工作\无限画布\Infinite-Canvas`、
`root_fingerprint=43c5720d9219b130`、`pid=13536`、`version=1.1.4`，
且 `repo_url`/`sources`/`update_notes` **原样保留**。
