## §3 See-through 调研：用它校准 P5 实现方向（本轮主交付）

> 交付物：`output/see-through原理对照与拆分元素优化方向-20261017.md`

### 对象
- 论文 **See-through: Single-image Layer Decomposition for Anime Characters**
  （ACM SIGGRAPH 2026 条件接收，arXiv:2602.03749）；仓库 `shitagaki-lab/see-through`；
  ComfyUI 封装 `jtydhr88/ComfyUI-See-through`（MIT）。
- 单张**动漫角色**图 → 最多 23 个语义透明层 + 深度 + 分层 PSD，供 Live2D 绑定。
- 训练 9,102 个 Live2D 模型 / 8×H200；显存默认 12–16 GB（1280 bf16），`group_offload` ~10 GB；
  耗时论文 74s+10s（4090）、ComfyUI 实测 138s（5090，1280/30 步）。

### 四支柱原理（可迁移的方法论）
1. **fully inpainted layers**：层 = 可见 + 幻觉补全，**与透明层一体生成**（`D_a` 透明解码器同时出 alpha
   与 padded Gaussian RGB），**不是后处理补洞**；LaMa 只补"深度细分后新暴露区域"。
2. **Body Part Consistency Module**：19 个部位 latent 沿"部位维 c"堆叠，U-Net 每个空间注意力块后
   沿 c 维做注意力 ⇒ 跨层联合去噪。消融：**Mask Dice loss 0.6480 → 0.3855（−40.5%）**，
   LPIPS 0.1952→0.1549，PSNR 16.24→18.30。
3. **pixel-level pseudo-depth**：Marigold 微调，**两阶段**（单类深度 → 跨类尺度统一，复用支柱 2 的模块）；
   伪深度在**细粒度 ArtMesh 级**，非粗类级；AbsRel 0.1549→0.0943。
4. **Depth-guided Layer Stratification**：否掉 z-buffering（会碎成小块）与整部位 z-sort（无法表达三明治），
   改用类内 **K-Means(K=2)** 分前/后 strata，解决 interleaving hair strands。

### 🚨 核心判断（写进文档 §0）
**我们做的是「像素归属」，它做的是「层生成」。**
- 归属观：原图是唯一真相，把像素分给各层 ⇒ 层**天然不完整**（被遮挡处没像素可分）。
- 生成观：每层是独立完整图像，原图只是合成结果 ⇒ 层天然完整。
- ⇒ **用户移开元素时我们露出一个洞，它露出被挡住的那部分元素。界面怎么改都治不了这个。**

### 我们侧的硬证据（对照用）
- `backend/element_extract.py:52-90`：`elementRGBA = sourceRGBA × ownershipMask` —— **零补全**，
  全层 `visible_only`。
- `backend/element_ownership.py:159-274`：`resolve_ownership` 按优先级**从高到低单向涂抹**，先涂者占位，
  **不可回头**；同档 + 置信度差 < `CONTEST_MARGIN(0.08)` ⇒ 判 `unknown`（交错结构直接丢弃）。
- `depth` 是**手工字段**，demo 写死；`_depth()` 只负责读。

### 六个优化方向（文档 §4）
| 方向 | 内容 | 成本 | 依赖 |
|---|---|---|---|
| **A** 完整性契约 | element 加 `completeness`（`visible_only`/`completed_local`/`completed_model`），界面显示「移开可能露洞」 | 低（半天） | 无 |
| **B** 跨层一致性复核 | 后验算 `fillRatio`(<0.15) 与 `fragmentation`(<0.60) 两个病态指标，命中则把争议像素**降级为 unknown**（默认不做激进重算） | 中（1–2 天） | 无 |
| **C** 深度可推断 | 零模型级：从 ownership 标签图**边界切断关系**推断 `in_front_of`；模型级（P5）：独立伪深度通道 + **两阶段统一尺度** | 中 / 高 | 无 / P5 |
| **D** strata 拆分 | 交错元素对做 K-Means(K=2) 拆 `#front`/`#back` 子层 | 中高（3–5 天） | C 必须先 |
| **E** ComfyUI 可选通道 | 项目**已有** ComfyUI 通用工作流提交能力；打包 `seethrough-basic.json` 作模板，产物走同一条 element_document 装配链 | 中（2–3 天） | 用户本地有 ComfyUI |
| **F** 三字段对齐 | `semanticLabel` / `drawingOrder` / `completeness`，界面才有东西可显示、导出 PSD 才有正确层序 | 低 | 与界面改造同批 |

⇒ P5 验收标准改为：**每层完整 + 顺序正确 + 移开不露洞**，而不是「能拆出 N 层」。

## §8 后端代码盘点与优化方案（老板：不用补测试，查整理优化方案）

> 交付：`output/后端代码整理与优化方案-20261017.md`。**只盘点，未改任何代码。**

### 量化现状（实测）
- **`main.py` 30144 行 / 228 路由 / 1151 顶层函数 / 100 个 BaseModel** —— 是 `backend/` 全部 10195 行的 **3 倍**。
- `backend/` 19 个模块，最大的 `element_text.py` 1403 行；`split_surfaces.py` 1031 行。
- `except Exception` **367** 处、裸 `except:` **8** 处；`raise HTTPException` **645** 处、`JSONResponse(status_code=` 仅 **7** 处（两套风格并存）。
- **7 个全局内存 store**；最大函数 `canvas_video` **487** 行、`run_split_layers_task` **468** 行、`rollback_update` **416** 行、`codex_permission_args` **328** 行。

### 🚨 发现一个真缺陷（不是风格问题）
**`read_text_attachment` 重名定义了两次**：`L6023`（默认 `AGENT_FILE_INLINE_CHARS`）与
`L12009`（默认 `MAX_ATTACHMENT_TEXT_CHARS`）。Python **后定义覆盖前定义** ⇒ L6023 那份**完全失效且无报错**。
如果 Agent 工具是按前者设计的，截断长度已经跑偏。⇒ 这是「单文件 3 万行」的典型代价：
相隔 6000 行的同名函数，人和工具都发现不了。

### 六个问题（按严重度）
① 重名函数静默失效（🔴 真缺陷）② 8 个 300–500 行巨型函数 ③ 错误处理三套风格并存
（645 HTTPException / 7 JSONResponse / 若干 200+ok:false —— P4 踩过的 `api()` 坑就源于此）
④ 7 个内存 store **没区分"任务态"与"缓存"**（5 个任务态丢了用户可感知；`SPLIT_TASK_STATE` 丢失
⇒ 重启后 `/repair` 必 409 是已知问题）⑤ 367 处宽泛捕获 + 8 处裸 except
⑥ 两套拆分实现并存（`split-layers` 17 端点 + `element-documents` 16 端点，两套数据模型/状态机/错误语义）。

### 优化方案（核心只有一条）
**把 `main.py` 拆成 8 个 router**（`canvas`/`assets`/`ai`/`projects`/`skills`/`split`/`system` + main 只留装配/中间件/startup/ws），
`main.py` 预期 30144 → **2000–3000 行**。做法必须**一次一个 router、搬一个验一个**，
先只搬路由函数（辅助函数用反向 import 过渡），全部搬完再下沉。

### 🚨 明确"不要做"的（避免过度重构，已写进文档 §4）
① 不引入 DI / service-repository 分层（本地单体应用，只会 3 万变 5 万）；
② 不一次性重写 main.py（228 路由、测试只剩 204 个兜不住）；
③ 不把 645 处 HTTPException 全换自定义异常（纯搬运零收益）；
④ 不动 `backend/` 的扁平结构（19 个模块已经很好读）；
⑤ 不引入 Celery/RQ（单机桌面应用，`asyncio.to_thread` + 任务态落盘足够）。
