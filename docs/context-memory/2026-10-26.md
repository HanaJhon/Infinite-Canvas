## 一、取消 agent 图片数量强规则，改由理解模型判断

老板：「取消 agent 中图片数量强规则，改为理解模型判断用户需要生成图片的数量」（截图圈的是参数面板的「张数 1/2/3/4」）。

### 强规则原来有四处
1. `agentState.genCount` 默认 **1**
2. `resolveFinalGenCount()`：`Math.max(1, Math.min(8, Number(genCount) || 1))` —— 永远回落到 1
3. `processAgentLlmResult` 的 **3c**：`else if(requestedCount === 0 && !agentWantsMultiDirection()) parsed.prompts = slice(0,1)`
   —— 用户没说数字、记忆也不要多方向时**硬截成 1 条**
4. 提示词 `_finalCount`：`Number(agentState?.genCount)` 遇 `'auto'` → NaN → `|| 1` → 又把模型按回 1 张

### 改法
- `agentState.genCount` 默认改 **`'auto'`**；参数面板「张数」加一个 **「自动」** 按钮（放最前，5 列）。
- `resolveFinalGenCount()`：
  - 用户原话说了数字（`chatRequestedImageCount > 1`）→ 用它（真需求，保留）
  - 面板显式选了 N → 用它
  - **否则（auto）→ `{count:0, source:'model'}`**，交给模型
- **3c 重写**：只保留「用户原话说了数字」和「面板显式选了 N（含 1）」两档；
  **面板是 auto 时完全不截**，模型给几条就是几条。
- 提示词两处：`_finalCount` 用 `_fcAuto` 判断，auto 时写「**由你判断**（没特别要求就填 1）」；
  Skill 提醒里 `_finalCount.count > 0 ? '由系统决定（N张）' : '**由你判断**'`。
- **老 localStorage 迁移**：`genCount:1` 是旧默认值不是用户选择 ⇒ 一次性标记 `_genCountMigrated`，
  首次加载把 `1/空/undefined/null` 改成 `'auto'`；迁完用户仍可显式选 1（标记存在就不再改）。

### 为什么必须迁移
BH.27 的老坑：改默认值救不了存量 localStorage。不迁移的话老用户 `genCount:1` 一直命中
`resolveFinalGenCount` 的显式分支 ⇒ 永远 1 张，改了等于没改。

## 三、🚨 挖到「从来没有 Release」的真正根因，并完成发布

老板第三次说「继续完成未完成的任务」。我把最后一步（push + Release）也做了 —— 结果挖出真相。

### 🚨🚨 根因：`gh` 的默认仓库是 **upstream（hero8152）**，不是 origin（HanaJhon）
```
git remote -v  → origin   = HanaJhon/Infinite-Canvas
                 upstream = hero8152/Infinite-Canvas
gh repo view --json nameWithOwner → {"nameWithOwner":"hero8152/Infinite-Canvas"}
```
所以之前**每一次** `gh release create` 都在往**原作者仓库**发 → 无权限 → `HTTP 404: Not Found`。
老板大概试过几次都失败，就以为「tag 推上去就行了」，于是 1.2.0/1.2.1/1.2.2 全都只有 tag、没有 Release
⇒ `releases/latest/download/update.json` 一直 404 ⇒ **所有用户从 1.2.0 后没收到过更新**。

**修复**：`gh repo set-default HanaJhon/Infinite-Canvas`（一劳永逸），
且**发版命令一律加 `-R HanaJhon/Infinite-Canvas`** 双保险。

### 另一个被推翻的旧经验
技能里写「工具会话内 `git push` / `gh` 会无限挂起，必须老板本人执行」——
**现在不成立了**：`git push origin main` **90 秒内成功**（`b9cfd20..109425b`），
`gh release create` 上传 126 MB **39 秒完成**。以后可以直接做，不用等老板。

### 发布结果（已上线）
- `git push origin main` → `b9cfd20..109425b` ✓（只有「exe > 50MB」的常规 warning）
- `gh release create Official.1.2.3 -R HanaJhon/Infinite-Canvas` → 成功
- Release 资产三个齐全：Full **125.85 MB** / Update **0.74 MB** / update.json ✓
- **tag `Official.1.2.3` → `109425b`**（正确提交）✓
- 本地 HEAD == 远端 main == `109425b` ✓
- **线上入口实测**：`https://github.com/HanaJhon/Infinite-Canvas/releases/latest/download/update.json`
  → HTTP OK，version **1.2.3**、delta(from 1.2.2, 0.74MB) + full(125.85MB)、notes 14 条 ✓
- 旧 tag `Official.1.2.1` / `1.2.2` 仍指向 `b9cfd20`（tag 位置错，但**对应的 Release 资产是好的**，

⚠️ 教训 1：**`gh` 命令的默认仓库要显式确认**（`gh repo view`），fork 过的仓库尤其容易踩。

## 十二、点击胶囊第三轮：改用**捕获阶段**（2026-10-26）
老板：「点击仍然无变化，**只有预览图正常显示**」⇒ **CSS 生效了，新 JS 也确实加载了**
（`smart-canvas.html` 里 `?v=1.2.3.1793005726` 已同步到改动时间，不是缓存问题）。

⇒ 问题在**点击事件到不了监听器**：消息区里某些子元素（编辑按钮等）会 `stopPropagation`，
`document` 上的**冒泡阶段**监听收不到。

**修法**：`document.addEventListener('click', handler, true)` —— **第三个参数 true = 捕获阶段**，
先于所有冒泡阶段的 `stopPropagation` 执行。
同时给 `openImagePreview` 包了 `try/catch` + `console.error('[AgentChip] openImagePreview 失败', err)`。

🚨 **通用教训**：给「可能被局部 handler 拦截」的区域挂全局点击（消息流、富文本、可编辑区），
**一律用捕获阶段**，别用默认冒泡。
