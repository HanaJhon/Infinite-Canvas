## §4 文字层「颜色/位置/字体粗细没还原」根治（AR.1k）

老板截图再报：`PS中的文字层没有还原` + `拆分图层中的参数，颜色、位置、字体粗细...等`。

**根因**：`splitLayersLayerDataUri()` 的 identity 直通
（`splitLayersIsIdentity(layer) && layer.url` → 直接返回原图 url）**没有排除编辑态文字层**。
编辑态文字层的 `layer.url` = 后端裁的**旧像素**（只给「还原像素」用），
而画板渲染的 span 是拿估出的字体/颜色**重画**的 —— 判 identity 就直通 ⇒ Photopea 永远拿旧像素。

**修复**：`rendersOwnUrl = layer.kind !== 'text' || splitLayersIsPixelText(layer)`，
只有「渲染源就是该 url」的两类（普通图片层 / 像素态文字层）才允许直通。

**反证**：把修复退回 `rendersOwnUrl = true` 后，三套检查同时报错
（DOM 1 项 FAIL、静态守卫 2 项 FAIL、Node harness 2 项 FAIL）→ 证明守卫真的能抓。

# §16 事故修复：网页能出结果、项目恒报「上游没有返回 GLB 下载地址」

## §16.1 现象
老板截图：**浏览器里在 Space 上点按钮能正常出 3D 结果**，但项目里 3D 节点红字报
「上游没有返回 GLB 下载地址」。⇒ 说明不是额度问题，是**我的解析代码**有 bug。

## §16.2 根因（溯源到 Gradio 源码，铁证）
`gradio/components/download_button.py`：
```python
def postprocess(self, value):
    return FileData(path=str(value), orig_name=Path(value).name)
```
🚨 **只返回 `path` + `orig_name`，根本没有 `url` 字段！**
前端 chunk（`assets/index-*.js`）里逐字可见它自己拼：
```js
url: `${host}${api_prefix}/file=${path.split('/').map(encodeURIComponent).join('/')}`
```
而旧 `_find_url()` **只在返回结构里搜 `http…glb` 字面量** ⇒ 对 `Downloadbutton` 必然落空
⇒ 抛「上游没有返回 GLB 下载地址」。**与网络/额度无关。**

## §16.3 顺手挖出的另几处链路错误（都按 `/gradio_api/info` 实测更正）
| 端点 | 旧代码 | 实测（`named_endpoints`） |
|---|---|---|
| `enable_model_exports_2` | 传 1，取 `[1][2][3]` | **0 参数**，只 2 返回 `[Downloadbutton, Number]` |
| `extract_model` | 传 **3** 个 | **2 参数** `(mesh_simplify, texture_size)`，1 返回 |
| `materialize_export_payload` | 传 1 | **0 参数**（靠服务端 `gr.State`），1 返回 |
| `finish_glb_export` | 传 **3** 个 | **1 参数** `(status_text)`，2 返回 |
| `generate_stl_download` | 传 2 | **看起来是 0 参数**（`info` 的 parameters 为空，不传也不报 422） |

🚨 **教训**：`/gradio_api/info` 的 `named_endpoints` 里 **`gr.State` 参数被 Gradio 自动剔除**，
`parameters` 的个数就是该传的个数 —— **不要凭 UI 组件编号去猜**。

## §16.4 修复
`hf_3dai_client.py`：
1. `_find_url()` 扩展：同时认 ① 字面 http ② `FileData.path` ③ 裸路径字符串；
   dict 里**优先 `url`、其次 `path`**。
2. **新增 `_find_file_url()`**：命中的裸路径按 `/` 分段 `quote(seg, safe="")` 编码后拼回
   `{SPACE_HOST}/gradio_api/file=<encoded>`（**与 Gradio 前端逐字一致**）。
   路由依据：`@router.get("/file={path_or_url:path}")` → 非 http 走 `file_fetch`。
3. 链路参数/取值按上表更正；`finish_glb_export` 改传 `[glb_text or "done"]`。

## §18 多图并组连接修正（用户请求 D：「多图并组连接还存在问题」）

### §18.1 根因（**按节点取图 vs 按图取图**）
- 用户场景「**多图并组**」= 多个上传节点先并成一个 `smart-group`，**group 再连到 3D 节点**。
- `inputNodesFor(3dNode)` 此时只返回 **1 个 group 节点**（不是 N 个上传节点）。
- 老 `smart3DConnectedViews` 对每个 input 只取 `imageRefsOnly(...)[0]` **第一张**
  ⇒ `length === 1` ⇒ `multiView = false` ⇒ **退回三视图老路**，
  且 group/上传节点通常没配生图模型 ⇒ 直接报「上游没有返回 GLB 下载地址」。
- 🚨 **这正是用户看到的现象**，也解释了为什么单上传节点的旧截图报同样文案（都走三视图老路）。

### §18.2 修法（`static/js/smart-canvas.js`）
```js
// 按「图」收集，穿透 group 展平（见 outputImagesForNode 的 smart-group 分支）
inputNodesFor(node).forEach(input => {
  imageRefsOnly(outputImagesForNode(input,false,smartLoopContext)).forEach(ref => {
    const url = String(ref?.url||'').trim();
    if(!url || seen.has(url)) return;
    seen.add(url); urls.push(url);
  });
});
return urls.slice(0,6);
```
- 覆盖三种连法：① 1 上传节点(1图) → 三视图老路；② N 上传节点各 1 图 → 多视图；
  ③ **1 个 group 含 N 图（多图并组）→ 多视图** ✅。
- `imageRefsOnly` 内部上限 `SMART_REFERENCE_IMAGE_MAX = 20` > 6，不会截断。
- 徽标/空态/隐藏下拉的判定都复用 `smart3DConnectedViews` ⇒ 自动跟着修好，无需另改。
