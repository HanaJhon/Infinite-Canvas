### 🚨 先说最关键的事实：Grsai 根本没有模型列表接口

实测穷举探测（带 key、显式 UA），**全部 404**：


该域名（`grsai.dakka.com.cn`）下**真实存在**的只有：

### 关键设计决定（踩过的坑）

1. 🚨 **chunk 名是内容哈希的** → 缓存里记一份 `chunk_url`，命中时只发 1 个请求；
   对方重新部署后哈希变化 → 抽不到 → 自动回落到「取页面 → 并行找 chunk」。
2. 🚨 **必须并行扫 chunk**：实测 grsai.ai 单请求 TTFB 就有 **5~16 秒**，
   串行扫 16 个 chunk 要 **3 分 20 秒**；改成 `Chunk(4)` 分批 `Task.WhenAll` 后，
   整体（取页面 + 找到 chunk）**降到 ~2 秒**。总超时 60 秒。
3. 🚨 **缓存放 `%LOCALAPPDATA%\InfiniteCanvasLauncher\grsai-models.json`，不放项目 `data/`**
   —— `data/` 是随发布包走的目录，release 扫描只允许留 `inspire_prompt_zh.json`，不能往里塞新文件。
4. 🚨 **分类关键词表必须与前端 `Qe()` 逐字一致**（源码在 `dist/launcher/assets/index-*.js`），
   否则 C# 写进 `api_providers.json` 的分类会和界面重新归类的结果对不上：
   - video: `video runway gen-3 gen3 gen-2 luma kling sora cogvideo hailuo minimax-h3 pika vidu animate svd ltx hunyuanvideo`
   - image: `image flux dall-e dalle sdxl stable-diffusion midjourney kolors paint draw diffusion banana art`
   - 其余 → chat
5. 🚨 **写配置「只增不减」+ 先备份**：只动 `id/name/base_url` 含 grsai 的那个通道，
   只往三个数组里 append，绝不删；写前 `File.Copy` 到 `%LOCALAPPDATA%\InfiniteCanvasLauncher\api_providers.bak-<ts>.json`；
   **无新增时一个字节都不写**（幂等）。
6. **`source` 字段复用前端既有分支**：返回 `source="remote"` 时前端 toast 自动变成
   「🎯 成功拉取并自动归类 N 个可用模型！」；`"curated"` 才走内置提示 → **前端无需改**。
7. `NavigationCompleted` 可能多次触发 → 用 `Interlocked.Exchange` 一次性守卫（不是 SemaphoreSlim）。

## §2 拆分图层「点完没有任何显示」根因 + 标题栏三项 UI 修改

### 根因（已坐实）：不是坏了，是**太慢**，前端先放弃

- `static/js/smart-canvas.js:10079` `SPLIT_LAYERS_TIMEOUT_MS = 20 * 60 * 1000`（**20 分钟**）。
- `auto` 模式实际耗时 ≈ **35 分钟**：analyze ~10s + erase 9 个文字 ~2min + refine 9 个 ~10min +
  extract **47 个元素每个一次生图模型调用**（成功约 30s/个）≈ 23min。
- **证据（`assets/output/` 里的中间文件时间线）**：老板那次 10-09 **09:32–09:42 产出 8 个 `split_text_*`**（refine 阶段）、
  **09:45–09:56 产出 25 个 `split_layer_*`**（extract 阶段，速率 2~3 个/分钟）→ 它确实跑到了提取阶段，
  09:3x 起算到 09:56 ≈ 26 分钟。**前端在 20 分钟时就已放弃并报错**，所以界面永远空白。
- **`local` 模式对照：47/47 图层全成功，只要 2 分 37 秒**（`mode:'local'` 直接跳过全部模型调用，
  本地去背质量够用，`transparent` 0.995~1.000）。
- 失败文案链路：`splitLayersFail()` 的**状态栏恒定写「拆分失败」**（不看 message），toast 才是 `message || 「拆分失败」`；
  后端失败一定写 `error: str(detail)`（非空）→ 所以**显示笼统「拆分失败」只可能来自前端超时那条路**。
- ⚠️ `split_erase_text` / `split_extract_element` 里模型调用**都吞异常**（失败就退回本地去背），
  它们不会把任务打成 failed；`split_call_image_model` 只对「被拒类」错误（credits/quota/余额/unauthorized/not found）换通道，
  **超时类 524/502 直接 `break`**（怕重复扣费）。
- 结论：要让 auto 模式可用，必须**并行化**（extract/refine）或**加「快速(本地)/精细(模型)」开关**。

## §3 拆分图层「层数可选（最低 3）+ 背景层」—— 2026-10-09 下午

**需求原话**：「允许用户选择拆分图层数量最低3层基础层分级：文字（如果有的话）-前景-背景，没有文字则从前景中细化拆分，以此类推」

### 语义定稿（`N` = 用户选的层数，= **层级数**，不是最终图层条数）

- **背景永远 1 层**（最底层）；**文字按实际块数单独成可编辑文字层，不占 N**；**前景占剩下的层级**。
- 有文字：`前景 = N - 2`（文字 tier 1 + 前景 tier + 背景 1）；无文字：`前景 = N - 1`（前景 tier + 背景 1）。
- 实测 `N=3` → 背景1+前景1+文字6 = **8 条**；`N=6` → 背景1+前景4+文字6 = **11 条**。公式吻合。
  ⚠️ 所以下拉写「3 层」而结果有 8 条**是设计如此**，不是 bug —— UI 提示文案已写明「文字不占层数」。

### 🚨 背景层必须由**后端兜底生成**，不能交给模型（本轮踩到的真坑）

- 先写成提示词「背景固定 1 层…」，实测 `target_layers=3` **模型只回了 1 个元素层**（把背景并进了前景），
  背景层直接缺位。原因是同一段提示词里还有「层数宁少勿多：合并优于拆碎」，模型选了最省事的路。
- 最终做法（`run_split_layers_task`，extract 之后）：**背景 = `base_rgba` 直接落盘**，零模型调用、零额外耗时。
  ```python
  bg_url = await split_save_png(base_rgba, prefix="split_base_")
  background = {"id": "bg", "kind": "element", "name": "背景",
                "bbox": [0, 0, width, height], "url": bg_url,
                "method": "base", "detail": "整幅底图（最底层）"}
  out_layers.sort(key=lambda it: it["z"])
  out_layers = [it for it in out_layers if it.get("id") != "bg"]
  out_layers.insert(0, background)
  for index, item in enumerate(out_layers): item["z"] = index
  ```
  ✅ **顺手补掉一个老缺陷**：以前没有背景层，auto 模式抹掉文字的位置在合并图里是**透明的洞**；
  现在 `base_rgba`（已抹文字）当底图，合并图 = 原图，无损。
  ✅ **重排 z 是安全的**：z 在前端只用于排序、从不显示（已核 `smart-canvas.js` 三处 `.z`）。
  ✅ 提示词相应改为**明确让模型不要输出背景层**（否则会与兜底背景重复）。

  ```python
  suspects = [it for it in layers if it["kind"] == "element"
              and it["bbox"][2] * it["bbox"][3] >= width * height * 0.92]
  if suspects and len(suspects) < sum(1 for it in layers if it["kind"] == "element"):
      drop = {id(it) for it in suspects}
      layers = [it for it in layers if id(it) not in drop]
  ```

### ① 背景跟原图不同 —— 我上一版做法的根本错误

- **现场取证**：`assets/output` 里最近一次拆分的产出里，
  `split_in_65281f03eb.png`（1248×1248）是**原图**（花园里端茶的女人），
  `split_base_09810054ed.png`（1248×1248）却是**一张构图都变了的新花园**（没有女人、花的位置全变）。
- **根因**：我上一版把**整幅图 + 遮罩**交给生图模型，让它「重画一张干净底图」。
  但 gpt-image 这类模型拿到**全画幅生成任务会把整帧重绘**，不是只改遮罩区。
  提示词里写「black regions must stay pixel-identical」也拦不住。
- **修法（关键）**：`split_erase_elements` 改成 **局部重绘 + 按羽化遮罩只贴回遮罩区**：
  1. 遮罩 union bbox 外扩 `pad = max(64, 长边 × 0.25)` → 裁局部（模型只看到这一块，漂移最小）；
  2. `split_square_pad(crop, min_side=384)` 补方；**遮罩用同一套补方偏移**（`mask_sq.paste(mask_up, offset)`），
     否则模型看到的 1、2 两图位置对不上；
  3. 出图 → `split_unpad` → resize 回裁切尺寸；
  4. **`out = base_rgba.copy()` 后 `out.paste(patch, (x0, y0), feather)`** ——
     **遮罩外的像素直接沿用原图，逐字节相同**。这是「背景跟原图一致」的硬保证。
- 提示词同步改成局部裁切语境：`Image 1 is a CROP of a larger photo` +
  **`Do not re-render, re-style, re-compose, zoom or crop the picture`**。
- 🚨 **羽化半径是个坑**：`ImageFilter.GaussianBlur(σ)` 内部换算成 **3 次盒模糊**，
  实际影响半径 ≈ `3 × σ × 3√(2π)/4 ≈ 5.6σ`。σ=8 时遮罩外 **45px** 都会被模型输出部分覆盖，
  σ=12 时约 69px —— 那圈正是「背景跟原图不一样」最容易露馅的地方。
  **实测对比**：σ=8 → 外溢 43px；**σ=3 → 外溢 8~32px**。最终定 **σ=3**。
- 保留原有护栏：遮罩覆盖 >= 0.98 直接跳过（避免白花钱）、失败返回 None 回落 `bg_pure=false`。

### ② 不透明度「没有实质作用」—— 真 bug

- `splitLayersApplyLiveTransform()` 原先**只写 `node.style.transform`**，没写 `opacity`。
  滑块调的是 `splitLayersSetOpacity` → 它只调这个函数 → **DOM 上的 opacity 永远不变**，
  数值和 `layer.edit.opacity` 都变了，但画面纹丝不动。
- 修法：该函数同时写 `node.style.transform` 与 `node.style.opacity`（拖拽路径也共用它，无副作用）。

### ③ 文字层可编辑

- 新增 `#splitLayersTextBar`（在 `.sl-stage-bar` 与 `.sl-board-wrap` 之间），
  **只在选中 `kind==='text'` 的层时出现**：文案输入框 + 字号 + 颜色 + 加粗 + 对齐。
- 新增 JS：`splitLayersTextAlignOf`（归一化 left/center/right）、
  `splitLayersRenderTextTools`（显隐 + 回填）、`splitLayersEditText`（写字段 + 重排）。
  在 `splitLayersRenderSelTools` 末尾调用 `splitLayersRenderTextTools()`，所以任何重排都会同步。
- 🚨 **不回写正在输入的控件**（`el !== active` 才写 value）：每敲一个字都会重排画板，
  回写 value 会把光标弹到末尾，中文输入法还会把候选词打断。
- 🚨 **`[hidden]` 必须显式写 `display:none`**：作者样式里的 `.sl-text-bar{display:flex}`
  会盖掉 UA 的 `[hidden]{display:none}`（作者表优先于 UA 表），漏了这条编辑栏永远收不起来。
- 🚨 编辑栏占掉一行 → `splitLayersFitBoard()` 要重算，否则画板溢出。
- 改的都是 layer 上的字段，**导出 / 合成 / 铺到画布读同一份数据**，所以画板改完两边自动一致。
- 一致性：画板用 DOM 渲染、导出用 `ctx.fillText`，两边都必须**不自动换行**
  （CSS `white-space: pre` + 合成端按 `\n` 拆分），否则所见 ≠ 所得。

### 8.3 🚨 本轮最重要的实测发现：模型抠图会毁掉「像素优先」的还原度

真实 e2e（3011，`mode=auto`，4 层，`ep_1791516939807/gpt-6-astra` + `gpt-image-2.5`）：
**5/5 层可用、382.6s**（< 前端 20 分钟上限），粒度提示词生效（目标 4 层 → 元素 3 + 文字 1），
LLM 判定需模型抠图 → 自动调图像模型成功 2 层、1 层遇 502 **本地去背兜底**（降级路径按设计工作）。

**但** `reconstruction = {mean:3.915, max:251, bad_ratio:0.1326, ok:false}` —— 从上一轮的 `{mean:0,max:0}` 掉了。
原因：**LLM 把 3/3 个元素都判成 `need_model=true`**，而当前实现是「整层替换成模型重绘的像素」→
那两层不再取自原图 → 叠加 ≠ 原图。**同时这也意味着 `mode=auto` 实际上退化成「每次全量调模型」**（成本回归）。

离线对照实验 `output/spike/exp_split_alpha_only.py`（拿这次 e2e 的真实产物，不改生产代码）：

| 方案 | mean | max | bad_ratio | ok |
|---|---|---|---|---|
| A 现状（模型自己的 RGB + 自己的 alpha） | 3.915 | 251 | 0.1326 | ❌ |
| B 只取模型 alpha，RGB 换回原图同坐标 | 0.125 | 162 | 0.00446 | ❌ |
| C 只取模型 alpha + **与「洞」同口径二值化**（`v>0→255`） | **0.0** | **0** | **0.0** | ✅ |

结论（可复用的性质）：**「每层像素永远取自原图」+「alpha 与背景洞同口径」⇒ 叠加恒等于原图，
与模型轮廓准不准无关**。B 不为 0 是因为洞是二值的、而模型 alpha 是软边 → 半透明像素被压暗。
代价：模型轮廓若与原物错位，会切掉/多留原图像素（但**不会整幅漂移**）。

## §9 第六轮：文字层默认可编辑 + 编辑态保住字体/斜体/旋转 + 抠图取并集

老板原话：「文字图层不是可以直接编辑的状态，转为编辑状态后字体的样式和旋转角度以及倾斜的斜体角度
都没有保持不变，分层的图片抠图不够完整」。三个根因都拿他 16:59 那次运行的真实产物诊断清楚了。

### 9.1 根因一：文字层默认落在「像素态」→ 选中也改不动字

`splitLayersIsPixelText` 原本是 `textMode !== 'edit' && !!url`，而后端**写死了** `"textMode": "pixel"`
→ 默认渲染成 `<img>`，不是可编辑 `<span>`。老板要的是「选中就能直接改」。

**翻过来**（老板口径变更，2026-10-09）：

- 后端**不再写** `textMode`（缺省 = 编辑态）；前端判定改成 `layer.textMode === 'pixel' && !!url`。
- 代价说明：默认视图不再是「叠加逐像素等于原图」。像素态降级成「还原像素」按钮，点一下才切过去。
- 🚨 **像素态的盒子必须改成整幅画布**（新增 `splitLayersBoxFor`）：原来盒子是 bbox + 内联负偏移
  把全画布 PNG 挪回原点，那样**一旋转就把整幅画布绕着文字转起来**。现在像素态文字层
  与元素层同构（盒子=画布、纯 `<img>`、无内联 hack），旋转/缩放/拖拽全都对。
  切态时 `splitLayersSetTextMode` 要**重算 box**，否则 span 会被撑满整幅画布。
- `.text` 类只给「真的在渲染 `<span>`」的层；列表定位框改用 `layer.bbox`（像素态 box 是整幅画布，
  用它画框等于没定位）。

### 9.2 根因二：schema 里压根没有 font_family / italic / letter_spacing

提示词只让模型给 `font_size/font_weight/color/rotation/align` → 编辑态只能用系统默认字体、永远正体。

- 提示词补三个字段 + **17 串字体白名单表**（写给模型看）。
- 后端新增 `SPLIT_LAYERS_FONT_STACKS` / `SPLIT_LAYERS_FONT_DEFAULT` / `SPLIT_LAYERS_FONT_LOOKUP` /
  `split_norm_font_family()`。🚨 **必须白名单**：这个值会原样进前端 `style="font-family:..."`，
  不白名单等于敞开 CSS 注入口子。白名单外的值一律回落 `Arial, sans-serif`（不是原样透传）。
  查表大小写不敏感 + 允许模型只给第一个族名（`"Georgia"` / `"georgia,serif"` 都算命中）。
- 字距按喂图缩放换算回原图尺度，夹在 `[-0.3em, 2em]`。
- 前端三处消费同一份数据：`splitLayersTextNodeHtml`（span 内联）、`splitLayersDrawText`（`ctx.font`
  带 italic + 真实族名，`ctx.letterSpacing`）、`splitLayersInjectText`（Photopea `__t.font` /
  `fauxItalic` / `tracking`）。🚨 Photopea tracking 单位是 **1/1000 em** → 要 `px / fontSize * 1000`。
  新增 `SPLIT_LAYERS_PS_FONTS`（CSS 栈 → Photopea 字体名，17 条全覆盖），认不出回落第一个族名且每条包 `try`。

### 9.3 根因三：旋转角度 —— 模型给 0，得从像素量

新增 `split_measure_rotation(rgba)`：按 alpha 的**最小面积矩形**量倾角（粗到细三段扫 -45..45），
返回**与 CSS `rotate()` 同号**（顺时针为正）的度数。纯本地、零成本。

🚨 三个坑（都是实测踩出来的，全部写进 docstring）：

1. **内层循环的基准角必须先冻结进 `base`**：直接写 `a = best + i * step` 会让采样网格跟着 `best`
   漂移，实测把 25° 一路漂到边界 -45°。
2. **不能拿 bbox 长宽比当判据**：横条倾到 44° 时 bbox 也是方的，会否掉真角度。
3. **不能拿「bbox 填充率高 = 实心块」当判据**：老板 6 个文字层里 3 个带徽章底（填充率 0.85+），
   而那块圆角矩形的朝向**就是**文字的朝向，量它正合适。唯一要拦的是**旋转不变形**（圆/环），
   判据用「扫描区间 max/min」比值：圆/环 ≈ 1.0，真文字 ≥ 1.6，阈值取 1.15。
   ⚠️ 别用「±10° 邻域」当判据 —— 稀疏字形的邻域比值只有 1.077，会误杀真文字。

🚨 **接线时只补「模型给 0」这个洞**（`abs(model_rot) < 1.0 and abs(measured) >= 1.0`）：
模型读不出倾斜时填 0，但它一旦给出角度通常是真读到了；而像素实测在**碎片化 alpha** 上会退化
（实测：整图转 12° 后那个徽章字母的 alpha 混进了徽章边缘，最小面积矩形被斜边带偏，量出 0）。
只补 0 的洞 ⇒ 不会把对的改成错的。另外这一步在所有模型调用之后，取值加 `try/except` 兜一下，
别为一行值把整个任务炸掉。

**真实产物验证**（老板 16:59 那 6 个文字层）：Can/focu 片段 0.0、Nano Banana 0.0、
Woman portrait **-2.0**、Mahmud 徽章 0.0、9:16 徽章 0.0、Anya 徽章 0.0 —— 全部与目视一致；
另找出一张真倾斜的「Nano Banana」层，肉眼约 -8° → **实测 -8.1**。

### 9.4 抠图不够完整：模型轮廓只能「加」不能「减」

`split_model_outline_layer(src_rgba, model_full, base_full=None)` 加并集：
`alpha = ImageChops.lighter(alpha, split_layer_hole(base_full.getchannel("A")))`。
`extract_one` 里传 `base_full=(full if cut_ok else None)`。

根因：模型重绘会把主体整体挪几像素 → 它的 alpha 相对原图**错位**，单用会把头顶/手臂切掉、
另一侧多留背景。本地抠图是像素对齐的（不会错位）只是边界可能不干净 → 取并集最稳。
实测老板那次：本地抠图不透明占比 **60.4%** vs 模型轮廓 **30.7%**，并集 62.3% —— 之前被模型轮廓
整层覆盖掉的那版把大部主体丢了。
