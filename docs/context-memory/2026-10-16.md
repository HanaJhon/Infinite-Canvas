### 新增 `backend/split_background.py`（背景资产，纯 PIL 零模型调用）
- `detect_background_kind`：solid / gradient / radial / textured / complex

  - textured → 镜像延伸 + 残差邻域修补；
  - complex → 邻域扩散修补（**自适应降采样**：朴素全画布逐像素扩散 1200×900 要十几分钟）。
- 🚨 **`mirror_seam_error` 是必须的**：「有高频结构」≠「规则纹理」。噪声/照片细节也会被判

### 抠图质量（`backend/split_product.py` 扩展）
- `build_trimap` / `alpha_boundary` / `edge_contamination` / `refine_alpha`：
  只在**未知带**做 matting，按 `a = ((C-B)·(F-B))/|F-B|²` 估 alpha，
  再 `F' = (C - B(1-a))/a` **反解前景色**（去色边）——
  「原 RGB 直接乘 alpha」正是白边/灰边/黑边的来源。
  ⚠️ `a < 0.15` 区**不做反解**（除以小数会放大噪声成彩色噪点），保留连续 alpha。
- `three_background_check`：白/深灰/棋盘三背景**客观**验收。
  `halo(B) = |环带对背景对比度 − 核心对背景对比度|`（背景相关，物理上正确）。
- 🚨 **矩形残留不能只看填充率**：正方形主体的 alpha 填充率本来就是 1.0。
  必须叠加「边缘是不是旧背景色」才能区分「矩形兜底」和「方形主体」。
- 🚨 **内部孔洞不能拿「闭运算多出来的像素」算**：那会把一切凹形/环形轮廓算成孔洞。
  改成「从四边 flood-fill 标记外部透明区，剩下的才是孔」（与 `split_local_cutout` 同口径）。
- `product_quality(mask, size, contract, checks, objective)`：**客观结论 + 用户逐项确认**
  两者都过才 `quality_passed`（§7「任务结束不等于质量完成」）。

## §2 非纯色背景重建：分区清洁底板 clean plate（老板方案《非纯色背景重建与可复用背景资产方案-20261016》）

> 方案核心：背景不能是「一块颜色/一张模糊图」，必须是**分区、分表面、分来源的清洁底板**
> （`clean plate + 前景层 + 可选阴影层 ≈ 原图`）。§1 的 `build_background` 只看「整幅像什么背景」
> 再挑一个算法，遇到「浅色桌面上压着一块深色面板」就必然把面板色铺到底色上。

### 新增 `backend/split_surfaces.py`（~700 行，纯 PIL 零模型调用）
- 公开 API：`build_clean_plate(source, hole, *, protect_mask=None, colors=16, band_ratio=0.02,
  min_confidence=0.30, feather=2, work_limit=400000, region_masks=None)` → `(plate_rgba, regions, meta)`。
- **表面分类** `classify_surface`：`flat / gradient / grid / texture / panel / line / shadow / text / unknown`
  （判据 = 颜色方差 + 方向梯度 + 自相关周期 + 水力半径厚度）。
- **区域来源五态** `REGION_SOURCES`：`original / copied / fitted / inpainted / unknown`；
  `TRUSTED_SOURCES` 才允许参与采样。
- **按表面选最小算法** `_SURFACE_ALGO`（懒梯子落在像素层）：
  `median_fill`（flat/shadow/panel）/ `plane_fit`（gradient，3×3 正规方程自解）/ 
  `phase_tile`（grid，周期相位对齐复制）/ `same_surface_copy`（texture）/ `axis_extend`（line）。
- **同表面取样**：洞内像素只从**同一 label** 的可信像素取值（多源 BFS 限定在同一 label 内）。
- `meta` 字段：`holePixels / writtenPixels / unknownPixels / uncoveredPixels / workScale /
  surfaceCount / regions / unknownRegions / outsideChanged / maxDiff / changedPixels / barriers`。
- 区域记录：`{id, kind, surfaceType, label, pixels, bbox, polygon(4点), confidence, source,
  qualityState, algo, detail}`。

### 🚨 本轮踩到并修掉的坑（写下来是为别再踩）
- **恒返回 1 个区域**：可信区带 `band`，紧邻洞的像素拿不到标签 ⇒ 种子循环找不到种子。
  修正：传播范围改用「不可信区 = 洞 ∪ band」（`fillable = invert(known)`）。
- **跨表面取样（x=1000 取到底色）**：洞边缘恰好切在面板边界上时，几何最近取到**错误表面**。
  修正：加**边界屏障线** `_edge_barriers`，把穿进洞内的表面边界延长成屏障。
  - 屏障配对判据必须是「**与洞边界垂直**」(`_boundary_tangent` 点积最小)，
    **不是**「两点距离最远」—— 后者在矩形洞上会把四端点连成对角线。
  - 屏障的标签检测必须先把标签铺到 band 上（否则 5×5 窗口内无标签）。
- **点阵纹理整片丢失（560→0）**：① `_estimate_period` 用「相邻样本差峰间距」拿到**点宽 4px**
  而非**点距 16px** ⇒ 改成投影轮廓**自相关** `_profile_period`；② `_periodic_source` 用 `labels`
  校验候选源，而 `labels` 只覆盖不可信区、可信像素标签在 `label_map` 里 ⇒ 恒不匹配。修后 560→560、差异 0.00。
- **渐变被量化切成条带**：每带单独看都是 flat，走不到 `plane_fit`，还画出 32 条屏障。
  修正：`_merge_surfaces` 颜色合并。⚠️ 但**颜色合并必须限定在相邻标签之间**：
  否则「面板 + 顶部条」（色差 24、空间不相连）会被误并。
  稀疏纹理另按 `thinRatio ≥ 3.0` 且接触量大合并。
- **1200×900 面板被判 `thinRatio=25`（误判成 line）**：`n` 是**采样点数**不是真实像素数。
  修正：`nTrue = n × step²`。
- **该判 unknown 的没判出**：软性距离扣分只把 conf 从 1.0 压到 0.33（越过 0.30 门槛）。
  修正：加**证据面积硬闸** `region_px > 4 × nTrue ⇒ conf = 0`；`reach` 尺度改用**水力半径**
  `_surface_thickness = 2·面积/周长`（**不能用 bbox 短边**）。
- **大图面板被判 unknown**：`panel` 走 `same_surface_copy` 会吃距离惩罚。
  修正：`panel → median_fill`，且**距离惩罚只作用于复制类算法**
  （`same_surface_copy / phase_tile / axis_extend`），参数化算法（median_fill/plane_fit）不受影响。
- `UnboundLocalError: algo` —— `algo` 在使用后才赋值；把 `stype/algo` 两行移到 `_region_confidence` 调用之前。
- **区域像素账目不平（38145 ≠ 38400）**：`region-original` 用了 `w*h - hole_px`。
  修正：改为 `w*h - written - unknown_px`。
- **大洞性能**：`work_limit = 400000`，超了就把 BFS 放到**降采样图**上做，
  取值放大必须用 `NEAREST`（`BICUBIC` 会把纹理糊掉）。1200×900 实测 1.76s。

## §3 背景 AI 修补闭环：账本 + 状态机 + 前端四组状态（老板方案《背景AI修补仍未生效-原因与最优调整方案-20261016》）

### 做了什么
1. **后端账本/状态机**（上一轮完成，本轮回归）：`backend/split_bg_regions.py` 新增
   八态区域状态机 + `background_coverage()` 覆盖账本 + `effective_write_mask()` 写入范围校验 +
   `candidate_quality()` 六项质量门禁；`main.py` 加 8 条 background 路由 + 入库三道闸门。
2. **前端四组状态**（本轮）：`splitLayersCoverageGroups()` → `#splitLayersStatusGroups`，把
   「前景质量问题 / 背景 AI 调用与候选 / 背景覆盖像素 / 背景待处理像素」**分开报**，
   不再用一句「已修复 x/y（AI n 次）」糊过去。审核面板与结果面板共用同一个渲染器。

### 🚨 新学到的红线（别的模块也适用）

- **边界连续性比「外圈中位色」**，不是比「围着 mean 的那一簇」：外圈换成完全不同的颜色时，
  那个色根本不在簇里 → drift 恒为 0，「近处底色、远处深色板」这种最该拦的反而不报。
- **上下文只排除洞，不排除保护区**：指针压在表盘上时环带几乎全在保护区，排除掉环带就空了。
- **碎块必须有归属**：分区器靠屏障挡住的洞像素标签为 0，会被 `build_clean_plate` 算进
  「原图保留区」⇒ 以**原主体像素**身份留在背景里且**没有任何计数暴露**。`_claim_strays()`
  并入最近区域，`stats.unlabeledPixels` 恒应为 0（它是可执行断言，不是参考数字）。
- **空位测试需要两条证据**：相关系数（模糊复制）+ **区域主色 vs 周边背景色的差**
  （`regionContrast`）。50% 淡化没有 alpha、核心区方差为 0 ⇒ 相关系数必然算成 0，
  整类「半透明指针」漏检。容差取 `seam_tol=26.0` 同值，避免与接缝判据打架。
- 🚨 **「写了」≠「修好了」**：`score_candidate` 曾只要区域被写过就标 `repaired`，
  而 `compose_plate` 只拼 `repaired` ⇒ **没过检的区域被拼进 plate**。state 必须由
  「区域自己的检查过没过」决定（探针实测抓出）。
- 🚨 **验收口径必须由原图定义，不能由候选声明**：曾用候选自己的 `report["requiredChange"]`
  （只覆盖它写过的区域）验收 ⇒ 没写过的区域被静默漏掉 ⇒ **「修了一半」报成
  `original_plus_deterministic`**。改为 `empty_slot_test(source, source, removeCore)`，
  与空位测试同源同容差。
- **区域「零写入」有两种情形，必须分开**：① 该改的像素为 0 ⇒ 原样保留就是正确结果
  （低对比元素）⇒ `repaired` 且不计缺陷；② 有该改的像素却没写 ⇒ 真待修复洞。
  混在一起会把「本来就无需修改」误报成待修复。

### P4 与 P3 的根本区别（红线不同）
- **P3** 几何操作**只改四个数、一个资产都不建** ⇒ 红线是「**谁都不许换**」（资产 id + 双 sha256 不变 + `assetsCreated==0`）。
