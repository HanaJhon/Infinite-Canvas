2. 新增 `LoadSavedGrsaiModels()`：读 `data/api_providers.json` 里 Grsai 通道的
   `image_models + chat_models + video_models`。
3. 两处调用补传：探测端点（「拉取并自动归类」）与 `RefreshGrsaiModelsAsync`。
   （`ProbeGrsaiModelsJsonAsync` 是 static 诊断入口，未改。）

`videoResolution` / `videoModel` 切换时都把超长时长收回到 10 秒（新增 `param === 'videoResolution'` 分支）。

验证：`tests/test_grsai_video_specs.py`（12 项断言全过，含比例映射）。

### 📌 教训
**「范围参数」要连着别的参数一起看**。文档写「支持1~15秒」+「1080p最多10秒」，

## §10 遮罩（局部重绘）场景屏蔽 LLM 提示词扩写

- llmBlockedByInpaint(node) = Boolean(validNodeInpaint(node))
- promptNodeLlmActive(node) = node.llmEnabled && !llmBlockedByInpaint(node)
  ← 渲染与运行**统一走这一个**，避免两边判断不一致

## §14 第 11 条搜索改走 Bing（老板追加需求）

**需求原话**：「第11条搜索能否走bing.com」。

### 落地形态（不是单走 Bing，是 Bing 主 + DDG 并行）
- `AGENT_WEB_SEARCH_BACKENDS` 改成「引擎 → 备用入口元组」：`bing`（cn.bing.com → www.bing.com）、
  `ddg`（lite → html）。**备用入口在同一线程内顺序试，绝不并发打同一家**（并发必被限流）。
- 两套请求头：`AGENT_WEB_HEADERS_BASE`（人人发）+ `AGENT_BING_EXTRA_HEADERS`（**只发 Bing**）。
  🚨 全套浏览器指纹头 + `SRCHHPGUSR` Cookie 能让必应结果变对题，但**给 DDG 带上同一套头会慢 5 倍**
  （实测 5.5s → 27.5s），必须拆开。
- `web_search(query, limit, engine)` 新增 `engine` 枚举（`""` / `bing` / `ddg`），模型发现结果不对题可换引擎重搜一次。

### 🚨 必应的两个真实坑（这次实测出来的，以后别再踩）
1. **不要"有没有交集"，要"命中比例"**。必应被限流/判非浏览器时，会返回**只命中查询里一个词**的泛结果：
   搜 `nano banana 2 release date` → 整整 10 条全是「nano – Text editor」「nano编辑器教程」「nano – Downloads」，
   **banana 全丢**。原来的 `_result_overlap > 0` 闸门对这种垃圾**完全失效**（nano 命中了）。
   ⇒ 改成 `need = 1 if len(tokens)<=2 else max(2, len(tokens)//3)`，命中数 ≥ need 才留。
   实测：上述垃圾 3 条 → 留 0；正确结果 2 条 → 留 2。**整批不过门槛就返回空让上层换引擎**，不把垃圾交出去。
2. **单请求可能极慢**：本次沙箱 cn.bing 稳定 36.8s，DDG 16.9s（环境限速，非代码问题）。
   ⇒ `AGENT_WEB_ENGINE_TIMEOUT=20` / `AGENT_WEB_SEARCH_WAIT=15` + **结果够量后只再等 3 秒**（自适应宽限）。
   🚨 别用 `as_completed(timeout=…)` —— 它超时会抛 `TimeoutError`，**把已经拿到的结果全废掉**。
   必须 `concurrent.futures.wait(pending, timeout=0.5)` 轮询 + `break`。

## §16 「你好」被反問画风 + 偏好设置没入口（老板实机反馈）

**现象**：老板发「你好」，小抽AI 回「你的输入比较简略，请先选择一个风格方向，我再为你逐步完善：」并给
水墨风/油画风/赛博朋克/Q版卡通 四个按钮；另外保存过偏好后再也找不到修改入口。

### 根因（两个，叠在一起）
1. **前端硬覆盖**：`processAgentLlmResult()` 里有两处兜底把 parse 结果强行改成 4 个画风选项并改写 `reply`
   （原文案就是「你的输入比较简略…」）。触发条件是 `isVagueImageRequest(text)`。
2. 🚨 **`isVagueImageRequest()` 的判据本身是错的**：**字数 < 25 且不含风格关键词 → 判定"模糊生图需求"**。
   ⇒ 「你好」「在吗」全部命中。加上 `thinkingMode` 被强制常开（第 4 条），这条路径**每次对话必走**。
3. **系统提示词在教模型当生图收集器**：`agentSystemPrompt()` 的 thinking 分支写着
   `You are an AI image-generation agent in Thinking Mode (progressive dimension collection mode)`，
   后面还有整段「维度采集 / 每轮必须返回 options / 末尾必须追加自定义输入 / 选项示例[水墨风…]」。
   另有一句 `prompts 数组只返回恰好 1 条` —— 模型会理解成「每轮都必须憋一条 prompt」。

### 修法
- **重写 `agentSystemPrompt()` 的 thinking 分支**：只留「输出格式」；新增【身份】【最高优先级：先判断用户要什么】
  【禁止事项】【什么情况才允许追问（只有两种，最多一轮）】【素材不全自己补默认值】。
  出图数量那段改成「**只有这一轮确实要出图时才相关**…不出图的轮次直接把 prompts 留空」。
- **删掉前端两处画风覆盖**，换成：模型没给 prompts/options/generations ⇒ 就是普通对话，reply 原样展示；
  只有 `looksLikeGenRequest(text)`（用户确实说要画/生成/改图）才用原文兜底一条待确认提示词。
- `isVagueImageRequest()` **整个删除**，替换为 `looksLikeGenRequest()`：
  判的是「有没有要」而不是「像不像模糊需求」，并显式排除寒暄（你好/在吗/谢谢/ok…）。
- **偏好设置入口**：`#agentMorePanel`（右上「⋯」）新增 `#agentPrefBtn`「偏好设置」，点开前先
  `loadAgentProfile(false)` 拉最新。`openAgentProfileModal()` 分**首次 / 编辑**两态：标题「先花30秒…」vs「偏好设置」，
  按钮「保存并开始/以后再说」vs「保存/取消」。

### 🚨 关键经验
- **「短输入 = 生图需求」这类判据是灾难**：用户第一句话永远很短。任何"补全/扩写"逻辑都必须先判**意图**再判**信息量**。
