## 一、多账号系统（局域网多人使用）

老板需求：局域网访问需注册登录；**画布按账号隔离**；**工作流库共享**；**Agent 记录（含前置记忆）按账号隔离**；
**资产库分个人 / 团队**（默认存个人，可从个人加入团队）。

老板拍板的三个决策：
1. 存量数据 → **第一个注册的人接管**（自动成为 admin）
2. 资产文件 → **物理分开存**（个人 `assets/users/<uid>/`，团队 `assets/library/`）
3. **需要管理员角色**（管用户 + 重置密码）

### 架构

**新增 `auth.py`**（约 260 行）：
- 密码 `hashlib.scrypt`（N=2^14, r=8, p=1），格式 `scrypt$N$r$p$salt$hash`
- 会话：HttpOnly Cookie `ic_session` + `data/sessions.json`（**30 天**，重启不失效）
- `AuthStore`：用户表 `data/users.json` + 会话表
- `claim_legacy_data()`：首个账号接管存量（搬 `canvases/ conversations/ media_previews/
  agent_profile.json asset_library.json projects.json prompt_libraries.json agent_tools.json`；
  **不搬** `workflows/` 与团队资产库）

**`main.py` 改造**：
1. **`UserScopedPath` 路径代理**（关键设计）：
   ```python
   class UserScopedPath:
       def resolve(self):
           uid = current_uid.get()
           return os.path.join(DATA_DIR, "users", uid, *self.parts) if uid else os.path.join(DATA_DIR, *self.parts)
       def __fspath__(self): return self.resolve()
   CANVAS_DIR = UserScopedPath("canvases")   # 19 处引用一行都不用改
   ```
   🚨 实现 `__fspath__`/`__str__` 让 `os.path.join` / `os.makedirs` / `open` 全部自动生效。
   已 scoped 的：`CONVERSATION_DIR` `CANVAS_DIR` `MEDIA_PREVIEW_DIR` `ASSET_LIBRARY_PATH`
   `PROMPT_LIBRARY_PATH` `PROJECTS_PATH` `AGENT_PROFILE_FILE`
2. **`current_uid` 用 `contextvars.ContextVar`**（异步并发安全，**不能用全局变量**）
3. **鉴权中间件**（改 `no_cache_html_middleware`）：
   - `_auth_required(path)`：放行 `/api/auth/*` `/static/` `/assets/` `/output/` `/favicon*`
     `/login.html` `/accounts.html` 与静态后缀
   - 未登录：API → 401 `{need_login:true}`；页面 → 302 `/login.html`
   - 登录后 `current_uid.set(uid)` + **`ensure_user_dirs()`**（否则新账号目录不存在，listdir 会 500）
4. **8 个账号接口**：`status` / `register` / `login` / `logout` / `me` / `users`(GET) /
   `users/{uid}`(DELETE) / `users/{uid}/password`(POST)
5. **资产库 scope**：`_asset_library_path(scope)` → `personal`（scoped）/ `team`（`data/asset_library_team.json` 全局）
   - `GET /api/asset-library?scope=team`
   - `POST /api/asset-library/promote`（`{item_ids:[]}`，复制索引条目到团队库「团队共享」分类，按 url 判重）

**前端**：
- `static/login.html`：**首次访问自动切「初始化管理员」**（`/api/auth/status` 的 `need_setup`）
- `static/accounts.html`：账号管理（列表/新增/重置密码/删除）
- `static/js/smart-canvas.js` 末尾注入两段：
  - **用户菜单**（右上角悬浮，显示账号 + 管理员标记，点开有账号管理/退出登录）
  - **资产库「个人 | 团队」切换条 + 加入团队按钮**（`window.__assetScope` 控制 `loadAssetLibrary` 的 URL）
- `main.py` 加 `@app.get("/login.html")` 和 `@app.get("/accounts.html")` 路由
  （HTML 页面都是逐个注册的，**没有通配**）

if _is_admin_only(path):

## 十、🚨 删除工作流「点了没反应」

老板反馈：**工作流删除失效，点了没反应、东西还在**。

### 根因
`DELETE /api/asset-library/items/{item_id}` 只查 `load_asset_library()`（**个人库**），
而工作流已经改存**团队库** ⇒ 找不到 → **404** ⇒ 前端 `if(!res.ok) throw` 被吞掉 ⇒ 「没反应」。

### 修法
抽出 `_strip_asset_items(lib, ids, library_id="")`，**两个库依次扫**：
```python
for scope in ("personal", "team"):
    lib = load_asset_library(scope)
    removed = _strip_asset_items(lib, ids)
    if removed:
        for item in removed: remove_asset_library_file(item)
        save_asset_library(lib, scope)
        return {"library": lib}
raise HTTPException(404, "资产不存在")
```
单个删除（`DELETE .../items/{id}`）和批量删除（`POST .../items/delete`）都改了。
⚠️ `_strip_asset_items` 除了 `libraries[].categories[]`，还要扫**顶层 `categories[]`**
（团队库的「工作流」「团队共享」直接挂在顶层，不在 libraries 里）。

### 实测
`DELETE /api/asset-library/items/wf_1870431b544c` → **200**，团队库 2 条 → 1 条 ✓
（测试前备份了 `asset_library_team.json.bak-test`，测完已恢复成 2 条；临时账号 `__del_test` 已清理。）

### 🚨 教训
**「改存储位置」要连带检查所有增删改查**。这次只改了「写入 → team」和「读取 → team」，
漏了**删除**，直接导致功能失效。同类的还有 `items/move`、`items/{id}` PATCH（重命名）——
如果工作流要支持改名/移动，同样要扫两个库。

`gh release create` 会先 HEAD 预检，网络一抖就整条失败（重试两次都挂）。
**改用 API 直接建**（跳过预检）：
```bash
gh api -X POST repos/<owner>/<repo>/releases --input -   # body 里给 tag_name/target_commitish/name/body/draft
```
然后再 `gh release upload ... --clobber`（这次上传 126 MB 花了 **11 分 20 秒**，但一次成功）。
