### 1.1 根因①：抠图范围被硬裁在「LLM bbox + 6% 外扩」的矩形里 → 主体被切

证据链（可复算）：
- 由 `split_in_` = 722×722 且元素层 bbox 高 722 ⇒ **crop = (256,347)-(818,1069)**（562×722）。
- **模型掩码**重建后 bbox = `(256,347,818,1069)`；**并集产物** bbox 也是 `(256,347,818,1069)` —— 两者**恰好等于裁剪矩形**，且内容触满上下边。
- 反推 LLM bbox ≈ `[294,385,486,646]`（pad=38，486+76=562，646+76=722，`int(646*0.06)=38` 自洽）。
- 目视：裙摆下缘、左臂/茶壶被**切平**（直线边）。
- **结论**：裁剪矩形之外的像素任何算法都拿不到；bbox 一旦比主体小，主体必然残缺。

### 4.1 改动：背景层从「一律本地」改成**三段路由**

| 条件 | 走法 | method |
|---|---|---|
| `pure_background=False` | 整幅原图 | `base` |
| **LLM `background.need_model=True`** | **调图像模型**做 object removal（局部重绘 + 遮罩贴回） | `model` |
| 其余（LLM 说不用 / 模型失败） | 本地 `split_background_plate`（挖洞 + `split_local_fill`） | `local` |

**LLM 决策点**：`SPLIT_LAYERS_USER_PROMPT` 的 JSON schema 新增顶层
```json
"background": {"need_model": <bool>, "prompt": "<仅 true：交给模型的背景描述>"}
```
判定口径写进 schema：**纯色/渐变/天空/墙面/地面/虚化 → false（本地补更快更准）；前景背后压着复杂纹理（花园/人群/货架/密排文字/重复图案）或大片被遮挡 → true；拿不准填 false**。
`split_analyze` 解析后随 `{"canvas","layers","background"}` 一起返回；`run_split_layers_task` 取 `background_spec` 执行。

**遮罩口径**：模型路线直接传 `mask=hole` —— 就是 `split_background_plate` 顺手算出来的**各层 alpha 精确并集**，比 `split_element_mask` 按 bbox 画矩形准得多。
**提示词**：LLM 的 `prompt` **追加**在内置英文规则之后（与元素层 `cutout_prompt` 同一套路：内置规则不可覆盖）。
**失败**：`split_erase_elements` 异常向上抛，调用方 catch 后回落本地补洞，`bg_detail` 注明「已回落本地补洞」。
**`split_erase_elements` 重新接回主流程**（2026-10-09 曾被下线）；新增 `mask=` / `extra_prompt=` 两个可选参数，不传时仍走旧的 bbox 近似（兼容 `verify_split_bg_fidelity.py`）。

### 6.1 「规则 7 不生效」的真因：粒度段把它压掉了（本轮最关键发现）

上一轮加了提示词规则 7（界面覆盖物单独成层），但实测**没生效**。取证方式很干净 ——
**比对日志 `text_len` 与源码里提示词的实际长度**：
- 上一次运行日志 `[canvas-llm] text_len=3186`；源码 `SPLIT_LAYERS_USER_PROMPT`（2961）+ `split_granularity_prompt(3)`（225）= **3186，完全相等** ⇒ 规则 7 **确实发出去了**，是模型没照做。
- 真因在**粒度段自己**：`target_layers=3` 时它写「前景只输出 2 层：**只保留最关键的视觉主体，其余全部并进背景或并进同一层；宁少勿多，绝不细碎**」，而模型那次**正好只回 2 个 element**（还把工具条/图标/加号全并进同一条）→ 规则 7 被「其余全部并进同一层」吞了。

**修法**：给界面覆盖物也开一个豁免口（与既有的「文字不占这 N 层」同套路），并写明不许被那句吞掉。
`split_granularity_prompt` 的返回模板改成：
```
用户要的是 {n} 层 = 背景 1 层 + 前景 {fore} 层。背景层由程序自动补，你只负责前景、文字与界面覆盖物：
…
- 文字不占这 {n} 层：…
- 界面覆盖物（鼠标指针 / 光标 / 箭头这类小图形）也不占这 {n} 层：它们必须按规则 7 单独成层，
  不要被上面那句「其余全部并进背景或并进同一层」吞掉，也不要当成照片或背景的一部分。
- 层数宁少勿多：合并优于拆碎（但上面两条例外项不算在内）。
```
规则 7 同时补强它最可能的失效点（模型把指针当成照片内容）：
```
⚠️ 即使这个指针压在照片、人物或风景上，也**必须**单独成层 —— 它属于界面覆盖物，
不要因为「它叠在照片上」就把它当成照片内容的一部分而漏掉。
```
并把「逐个检查画面四角与图片上方」扩成「画面四角、工具条附近、以及任何标签或文字旁边」。

### 7.1 先纠一个方法错误（差点误导整轮结论）

自写的「从中心向外走、遇连续 ≥15px 暗像素即止」量边缘时，**左向行走返回值偏左 28px**：
`return x - run + 1` 在左向时算错了起点（run=15 时正确起点就是 `x`）。
症状：量出「真实卡片左缘 303」，而源图亮度剖面明明是 331（y=450：x=330 是 19、x=336 是 160）。
**教训**：拿自写测量当基准前，先跟源图剖面对一次数；右向行走那条恰好是对的（返回值 = 最左暗像素）。

### 7.2 「字体倾斜角度」= 后端给的 rotation 错，不是字号也不是斜体

**真值怎么钉死的**：全局 UI 倾角由**三条长边**独立量得，完全一致 ——
卡片上缘 **+1.27°** / 卡片下缘 **+1.26°** / 工具栏上缘 **+1.25°**（Theil-Sen 中位斜率）⇒ 真值 **+1.26°**。

| 文字层 | 后端(旧) | 真值 | 旧误差 | 新实测 | 新误差 |
|---|---|---|---|---|---|
| Anya标签文字 | **+6.0** | +1.26 | 4.74 | **+0.9** | 0.36 |
| 图片标题文字 | 0.0 | +1.26 | 1.26 | **+1.2** | 0.06 |
| 工具名称文字 · 9:16 | 0.0 | +1.26 | 1.26 | 0.0（闸拒收，保留原值） | 1.26 |
| 工具名称文字 · Nano Banana | **+3.0** | +1.26 | 1.74 | **+1.2** | 0.06 |
| Mahmua标签文字 | +1.0 | +1.26 | 0.26 | **+1.3** | 0.04 |

**平均绝对误差 1.85° → 0.36°。**

**根因**：旧的 `split_measure_rotation` 量的是**文字层自己的 alpha**，而那块 alpha 已被
① `split_clamp_alpha` 夹回 LLM bbox（+4px）、② 本地抠图把**底板亮边框**一起抠了进来
→ 最小面积矩形量到的是「这块残缺形状」的朝向。实测 Anya 的 alpha bbox 只有 56x24，量出 6.0°。
（另：后端存的 6.0/3.0/1.0 与 `split_measure_rotation(plate)` 的输出**逐位相同** ⇒ 确认这些值就是它写的。）

**改法**：新增 `split_measure_text_angle(src_rgba, bbox)` —— **只看原图那一小块，完全不碰 alpha**：
- 取亮度最高一档当墨迹（亮字暗底 / 暗字亮底两种极性都试）；
- 逐列取墨迹**上缘与下缘**，各做 Theil-Sen 稳健回归（点对斜率取中位），两角再取中位
  （上+下取中位是为了抵消降部 y/p/g 的偏置 —— 单看下缘会被降部拉斜）；
- 闸：有效列 ≥12、墨迹列高 > 0.75 框高则丢（那是底板/边框）、|角| >20° 则 None。

**踩过的三个坑（都写进注释了）**：
1. **极性不能按「哪一极像素多」选**：`Woman portrait` 的暗极有效列 197 > 亮极 166，但暗极拟的是背景（IQR 10.9 vs 亮极 7.6）。改成**按残差更小**的那一极选。
2. **残差 IQR 不能当「准不准」的闸**：文字墨迹天生高低不齐（升降部/标点/字间空隙），
   实测真文字 IQR 就有 5~9px —— 拿 `IQR > 2.5` 拒收会把**五块全拒掉**（实测过，全 None）。
   IQR 只用来挑极性；准不准靠「墨迹占框宽比例 0.30~0.92」（真文字实测 0.64~0.71）。
3. `pad` 要按**高度**取（`max(4, h*0.25)`）：按 `max(w,h)` 取会让宽文字（Woman portrait 227 宽）
   塞进大片背景 → 闸门拒收（实测全 None）。

### 7.3 「元素层边缘对齐」= ① L2 横跨整幅抄了原图卡片（双边缘）② L1 的 alpha 溢出真卡片

**① 双边缘元凶 L2**（数值钉死）：
- `L2 侧边参考图片卡片组` bbox `[0,82,1248,767]` = 画布 **61.5%**，`method=local`；
- alpha **硬二值**（>40 与 >128 覆盖率完全相同 = 23.79%）⇒ 本地抠图产物；
- **94.8% 的实心像素落在 L1（中央卡片）bbox 内**；
- 它在 L1 bbox 内的不透明像素与源图 **逐像素相同（平均绝对差 0.00）** ⇒ 就是原图卡片的一份硬边拷贝；
- z=2 盖在 L1(z=1) 上 ⇒ 合成图上出现**外层原图卡片 + 内层模型卡片**两条错开的边缘。

**成因**：LLM 把一**组**东西（左右两侧的参考卡片 + 中间的连接线）当成一个元素，
给了横跨整幅的 bbox；模型这条路失败（「模型输出不含有效透明通道」）→ 回落本地抠图，

**改法（闸）**：新增「组 bbox 抄邻居」去重 —— `method=local` **且** bbox 面积 ≥ 画布 40%
**且** ≥80% 的 alpha 落在别的元素层 alpha 里 ⇒ 丢出 `out_layers`。
离线复现：**只命中 L2**，其余 13 层全保留（L1 靠 `method=model` + 面积 33.5% 双重保护；
L3 工具条面积 3.2%、图标 0.0~0.1% ⇒ 都远低于阈值）。
⚠️ **只丢 `out_layers`、不删 `plate_by_id`** —— 背景层挖洞还要用它，少挖一块会让背景残留卡片。
（离线合成对照：`output/spike/diag_1010AA_guard_ab.png` + `_corner.png`，去掉 L2 后卡片右上角的灰白外圈消失。）

### 8.2 根因 A：多行文字层被前端当「一个段落」重画

  按 `字号 x 1.15` 的行距从盒子左上角**左对齐**排下来，再按墨迹盒拟合撑满 bbox。

### 8.3 根因 B：元素层被剪切成**平行四边形**（不是旋转误差）
- 量法（关键）：取 alpha 的四个极值像素 = 旋转矩形的四个角，算「竖边倾角」与「横边倾角」。
  **矩形**满足 `竖边倾角 + 横边倾角 ≈ 0`；剪切破坏的正是这个**垂直度**。
- 实测老板真实产物：竖边 **-10.02°**、横边 **+6.49°** ⇒ 和 = -3.5° ⇒ 剪切。
  源图真值（左右缘 Theil-Sen 各量一遍，-8.80 / -8.88）**8.84°**。
- 后果：右缘越往下越出卡片（y=303 外溢 4px、y=943 外溢 15px），画面上是**一条渐宽的缝**。
- 成因：`split_anchor_to_bbox` 旧口径 = 「按 bbox 长宽比反解一个角 + **非等比铺满**」。
  非等比缩放是仿射变换，**旋转过的矩形被它一拉就变平行四边形**。
- ⚠️ 我第一版对照断言写错了：拿「左右边是否平行」判剪切 —— **平行四边形照样左右平行**。已改成垂直度。

### 8.4 修法 A：让模型**逐处**给 bbox，再按它拆层

  所以没有 `lines` 就**原样返回**（宁可不动，也不要乱拆）。

  - 源图：上边 **+1.30°**（rms 0.21, n=216）、下边 +1.15°、左/右边 **−8.8°**（rms 0.29）。
  - 「横边倾角 + 竖边倾角 ≈ 0」这条**矩形判据在源图上根本不成立**（源图自己 −8.8+1.3 = −7.5）。
  - 旧口径产物横边落在 **+4.67°**，与源图差 **3.37° × 666px ≈ 22px**
    ⇒ 正好是右上角、左下角**各差一截**（老板圈的两处）。
- 🚨 **上一轮的「矩形化」救不了**：它把源图倾角当旋转角，产出的横边落在 +4.4°，源图要的是 +1.3°。
- **新口径（本轮主线）= 仿射映射**：把模型那块转正 → `Image.transform(Image.AFFINE)` **仿射映射**到
  「由源图实测竖边倾角 ta + 横边倾角 tb + 外接框 (bw,bh) 反解出的平行四边形」。
  仿射把平行四边形映成平行四边形 ⇒ 结果**必然**与源图同形同位。
  关键式：`den = 1 + ta*|tb|`、`hq = (bh − bw*|tb|)/den`、`wq = bw + hq*ta`；目标 Q0/qa/qb 与模型
  P0/a_v/b_v 定出 M 与 T，再求逆喂 `transform`。

### 9.3 路上挖出的三个真 Bug（都已修）
1. **`deg_mod = split_measure_shape_angle(alpha, list(box))` 单位传错**：`box` 是 `getbbox()` 的
   `(l,t,r,b)`，函数要 `(x,y,w,h)` ⇒ 在**偏到右下的空区域**上量、**恒返回 None** ⇒ 仿射整段被
   **静默跳过**、永远退回旧口径。修成 `[box[0], box[1], box[2]-box[0], box[3]-box[1]]`。
   （上一轮的回归脚本把这行 `list(box)` 当正确写法锁住了，所以一直没暴露。）
2. **仿射逆变换符号写反**：`cx = -(i00*(bx-tx) + i01*(by-ty))` ⇒ 产物横边 **+36.25°**、覆盖度 51.59%。
   正确：`p = Minv·(q − T)` 且 `q = (bx+X, by+Y)` ⇒ `cx = i00*(bx-tx) + i01*(by-ty)`（**不加负号**）。
3. 🚨 **`split_measure_shape_angle_h` 的「上下取均值」是错的**（本轮新发现）：
   - LLM 的 bbox 常把卡片边切掉几像素；同一张卡片 bbox 差 1~5px，横边量测就从 **0.51° 变成 None**。
   - 逐道闸装仪表（`probe_1010B_h_debug.py`）后发现：**上边那串干净**（恒 1.23~1.25°），
     **下边那串被卡片内部人像纹理带偏**（−0.44 / 0.0 / −0.15 乱跳）；取均值反而把 1.24 拉成 0.55。
   - 修法：**上边优先、下边兜底**（各自独立过 IQR 闸，**不取均值**）+ 带从 18% 收到 **12%**
     （18% 时连整幅图都会被误量出 0.0°）。修后 7 组 bbox 全部量到 **1.08~1.26°**，整图正确拒收。

## §15 新功能：「导出到在线 PS」（新标签页打开 Photopea 并载入全部图层）

### 15.1 需求与做法
老板：「添加导出到在线PS功能，用户可以通过该功能入口跳转到新的网页Photopea网页并打开此次拆分项目的所有图层」。
做法：复用已有的 PSD 生成（`splitLayersBuildDocument()` + `saveToOE("psd:true")`）→
把字节上传换一个 http 地址 → 新标签页打开
`https://www.photopea.com/#<encodeURIComponent(JSON.stringify({files:[psdUrl]}))>`。

入口两个（上次「找不到按钮」的教训）：
- 标题栏 `#splitLayersOnlinePsBtn`，紧邻「导出分层 PSD」；
- 图层栏底部 `#splitLayersOnlinePsSideBtn`，`.split-layers-side-foot` 改成列向两行
  （两个按钮都 100% 宽 —— 图层栏不宽，横向并排会把「铺到画布 · N」的角标挤掉）。

### 15.2 三个关键决策（都是踩过才定的）
1. **必须先把 PSD 落到服务端**：Photopea 只吃「它自己按 URL fetch 到的文件」。
   `blob:` 绑在当前源上、跨窗口取不到；`data:` 受 URL 长度限制（Chrome 约 2MB）。
   本机 `/assets` 实测返回 `Access-Control-Allow-Origin: *`（`CORSMiddleware(allow_origins=["*"])`），
   正是 photopea.com/api 文档点名要求的头。
2. **走 multipart `/api/ai/upload`，不走 `/api/ai/upload-base64`**：
   `_local_upload_kind_ext()` 对 `.psd` 返回 `(None, ".psd")`，而 `upload_ai_base64` 在
   `kind is None` 时**强制**回落成 `("image", ".png")` → PSD 顶着 `.png` 的名字，
   有被 Photopea 按 PNG 解析的风险。multipart 那条会原样保留扩展名。
3. **先同步开窗、再 await**：生成 + 上传要好几秒，等 await 回来 `window.open` 已出用户手势窗口，
   会被当弹窗拦掉。所以同步 `window.open('', '_blank')` → 写「正在准备 Photopea…」占位页 →
   准备好后 `win.location.href = target`；失败 `win?.close()`。
   ⚠️ 不加 `'noopener'`（加了返回 null，判断不出被拦截）。

⚠️ 前提：Photopea 是 https，取 `http://127.0.0.1/...` 靠 Chromium 把 localhost 当可信来源。
画布若用局域网 IP 打开，会被混合内容策略挡掉（表现为 Photopea 自己报打不开）。

## §22 🚨 老板是对的：`#STRING`（无效 hash）= 零广告的可用编辑器（2026-10-10）

| `#`（空） | 241 KB | 40 | 39 |
| `#{}` | 240 KB | 39 | 38 |
| `#{"environment":{…}}` | 241 KB | 39 | 39 |

## §24 ✅ 修复在线 PS 文字层位置偏移
根因：`splitLayersInjectText()` 在同一个 Photopea 脚本里建文字层后立即读取 `__l.bounds`；Photopea 尚未完成文字排版，bounds 为 0,0,0,0，定位退化成 `translate(box.x, box.y)`，导致文字整体偏移。
修复：建层脚本先结束并 `echoToOE('done')`；第二次 `pea.runScript` 再读取真实 `__l.bounds`，随后执行 translate / rotate / resize。新增 `check_split_static.py` 守卫覆盖该跨脚本约束。
验证：`node --check static/js/smart-canvas.js` OK；静态总检 ALL CHECKS PASSED；真实 DOM **98 项 ALL PASSED**；i18n 1291 keys；临时探针页已清理。未重启 3000 服务，未改版本号。

## §25 ✅ 二次修复在线 PS 文字层跑到画布外
用户截图显示上次修复仍完全不对。继续实测发现：Photopea `bounds[i]` 是 UnitValue 对象，不能直接参与 `box.x - bounds[0]`；必须取 `bounds[0].n` / `bounds[1].n`。已在 `splitLayersInjectText` 中转成 Number 后再 translate，并更新静态守卫。node --check、静态总检、真实 DOM 98 项、i18n 1291 keys 均通过；临时探针已清理。
